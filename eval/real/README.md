# eval/real，真实文献方法段（**语料不随提交材料分发**；脚本与本文档可分发）

## 这是什么

从 arXiv 抓取的**真实** MD 方法段，用于两件事：

1. **假阳性排查**：检查器在我们自己写的 case-01 上全对，只说明规则符合我们
   自己的预期，不说明它能读真实文献。真实写法千奇百怪，假阳性（把"本文体系
   不存在的问题"报成"缺失"）才是使用者放弃工具的首要原因。
2. **抽取质量评估**：在人工标注上计算真实的字段级指标，替掉原来 n=2 的标注集。

## ⚠️ 合规边界（重要）

`sections/` 里是**已发表论文的正文片段**，版权归原作者所有。
它们只用于本地评估工具质量，**绝不进入追光计划的提交材料**。

打包提交时**必须排除下面这些目录**（注意：不是排除整个 `eval/real/`，
这一层里的 `.py` 脚本是可分发的，见文末表格）：

```bash
# 打包：版本库与生成物不进提交，另排除含正文的三个目录与缓存
zip -r md-repro-checker.zip md-repro-checker \
    -x 'md-repro-checker/.git/*' \
    -x 'md-repro-checker/out/*' \
    -x 'md-repro-checker/eval/real/sections/*' \
    -x 'md-repro-checker/eval/real/_label_work/*' \
    -x 'md-repro-checker/eval/real/_scratch/*' \
    -x 'md-repro-checker/eval/_tmp/*' \
    -x '*__pycache__*'

# 自查：下面这条必须**没有任何输出**。打包错误是静默的，
# zip 不会告诉你它把 121 MB 的论文全文打进去了。
unzip -l md-repro-checker.zip | grep -E '\.git/|/out/|sections/|_label_work/|_scratch/|_tmp/|__pycache__'
```

这份排除表与包根目录的 `.gitignore` 是同一份清单，两处要同步改。
按它打出来的包正好等于 `git ls-files` 的 54 个文件。

> 早先这里写的是 `-x 'md-repro-checker/eval/real/*'`（排除整个目录）。
> 那与下方表格、以及主 README 中"`test_regressions.py` 可独立运行"
> 的说法直接矛盾，按那条命令打包，审阅者会被指引去找一个不存在的文件。

提交材料中只允许出现：**聚合指标**（如"假阳性 N 篇 / M 篇"）与 **arXiv ID**。
`manifest.json` 本身不含正文、只有 ID 与哈希，可以视情况保留；
`sections/`、`_label_work/` 与 `_scratch/` 一律不得分发。

（最长十余词）作夹具，足以触发对应正则，构不成对原文的复制。
因此它可以随工具交付，并在没有语料的环境里独立运行，
这一条很重要：它让"真实文献上发现的缺陷"变成了可交付的、别人能跑的测试。

## 用法

```bash
python eval/real/fetch_arxiv.py --list            # 只搜索看候选
python eval/real/fetch_arxiv.py --limit 30        # 抓取（遵守 arXiv 的 3 秒间隔）
python eval/real/fetch_arxiv.py --re-extract      # 改了抽取逻辑后重抽，不重新下载
python eval/real/fp_hunt.py                       # 假阳性排查
python eval/real/test_regressions.py              # 真实语料回归测试（不需要语料）
python eval/real/audit_case.py                    # 大小写/规范化审计（不需要语料）
python eval/real/validate_labels.py               # 打分前的标注体检（必须先跑这个）
python eval/real/score_real.py                    # 标注集上的状态/取值指标
python eval/real/score_real.py --adjudicated      # 按逐条裁定重算
python eval/real/inspect_sections.py <arxiv-id>   # 看某篇的章节树

# 改抽取逻辑时：改前改后各拍一张，逐格对账（不需要标注即可跑）
python eval/real/status_diff.py --snapshot --tag before
python eval/real/status_diff.py --diff before after --allow-ctx-derived
```

**先跑 `validate_labels.py`。** 一份格式错、或 evidence 对不上原文的标注，
会让之后每一步都建在沙上，而这两种错误光看指标发现不了（它们会伪装成
"工具判错了"）。校验器把 evidence 与原文的吻合分成若干档**分别计数**，
而不是通过/失败两分：逐字命中、省略号拼接、仅空白差异、排版字符差异
（`et al.’s` 的弯引号）、省去括号旁注（`(red online)`）、分隔符不规范、
压缩改写、无法定位。**分档而不是一刀切，是因为把合法的引用方式判成失败，
校验器自己就成了噪声源**，第一版就是这么错的：122 条逐字命中的旁边，
18 条合法引用被一起判失败，看起来像 38 处标注事故，实际是 1 条规则定错了。
另一头也要防：把"引文被压缩"与"编造原文"混为一谈。判据是**与原文是否
共享 20 字以上的连续片段**，编造的句子不会有。

`score_real.py` 默认打印**原始一致率**（未裁定），并把每一处分歧连同
原文证据句与标注备注列出来，先看分歧清单，再逐条裁定，最后才跑
`--adjudicated`。这一步不能省：把分歧直接算成工具的错误率就是自欺。

## 设计要点

**为什么走 e-print（LaTeX 源码）而不是 PDF。**
PDF 抽出来的文本会把上下标、公式、断行揉成噪声，抽取器的错误率里会混进大量
"PDF 解析错误"，而这些错误与工具质量无关。评估必须只测工具，不测解析器。
LaTeX 源码是作者写的原文，结构干净，是更公平的输入。

**为什么抓这么多不同领域。**
case-01 是"干态聚合物熔体 + 直接 NEMD"。工具在这一个场景上调对，
不代表在别的场景也对。查询按与 case-01 **不同的维度**铺开：
含配体的生物体系、膜、电解质、无机与低维材料、ReaxFF，
以及 Green-Kubo / RNEMD 等其它输运方法。
假阳性最容易出现在"字段不适用"的判断上，所以水模型、配体参数、
质子化态这三个语境字段必须各来一些正反例。

**没有标注怎么找假阳性。**
找一个**独立于被评估模块**的判据：词汇证据。
一段方法段如果通篇没出现任何"水/溶剂/水合"词，那么"水模型缺失"
就一定是假阳性，该体系根本不存在水模型。这个判据不看 `extract.py`
的判定结果，只看向量与文本本身，因此可以用来**证伪**它。
判据是单侧的：只判"必然不适用"，不判"必然适用"，
作者没写不等于不存在，那可能就是真的缺失。

## 一轮真实语料排查的结论

**语料**：45 篇缓存 → **24 篇可用方法段**。
不可用的 21 篇里，13 篇是**只有 PDF 没有 LaTeX 源码**的投稿，1 篇无 `.tex`，
1 篇不是 arXiv ID，其余 6 篇定位不到方法段。
13/45（约 30%）的 arXiv MD 论文只有 PDF，这是**语料规模的限制，不是工具缺陷**，
也正是"刻意不解析 PDF"这个选择成立的理由（见上文设计要点）。

**结果：24 篇中最终可疑项 0 篇。** 但这个 0 是修完之后的结果，
过程中暴露出来的问题清单才是这一轮真正的产出：

| # | 现象 | 性质 | 修法 |
|---|---|---|---|
| 1 | `"his" in low` 命中 "**this**"，20/24 篇（83%）被判"含蛋白" | 假阳性（最大来源） | 词边界 `PROTEIN_RE` |
| 2 | `explicit_solvent` 默认 True，14/24 篇（58%）无溶剂体系报"未报告水模型" | 假阳性 | 改为要求**正向证据** |
| 3 | 溶剂**现象词**（"hydrated surface"、"ion solvation"）被判成显式溶剂 | 假阳性 | 要求"溶剂作介质"构式 |
| 4 | `opc` 命中 "**dopc**"（磷脂），报出"水模型 = OPC" | **取值错误** | 短键加词边界 |
| 5 | 注释写着"只写族名 → ambiguous"，代码却一律报 present | 文档与实现不一致 | 真的产生 `ambiguous` |
| 6 | `"energy and pressure"` 独立成键，任何"能量与压力"句子都变 EnerPres | **取值错误** | 要求与 "correction" 同短语 |

`water_model` 的 `missing` 从 **17/24 → 0/24**，`protonation_state` 的
`missing` 从 22 → 2，`force_field` 有 2 篇正确地落进 `ambiguous`。

**一条需要如实说明的事**：这一轮里相当一部分工作量花在**修我们自己的
评估脚本**上，而不是修工具。`fp_hunt.py` 的判据本身也假设错过两次，
一次是把 `correlation_window` 当成 Green-Kubo 专有（R-03 原文涵盖了
NEMD 的稳态平均窗口，判据错、工具对），一次是担心色散校正召回不足
（详见下条）。**用来找假阳性的判据自己也需要在真数据上被证伪**，
这是这一轮最值得记下的一条方法论。

**一次被撤回的"修复"**：曾判定 `_extract_dispersion` 召回不足，
因为 `2404.14338v1` 里明明有 "dispersion correction" 却被报缺失。
逐篇核对后撤回：那句说的是 **dDsC，一种 DFT 层面的色散校正**，
与经典 MD 里截断 LJ 的长程校正（GROMACS 的 `DispCorr`）不是一回事。
真按原计划把通用说法加进词表，反而会制造一类新的假阳性，
**把量子化学术语读成 MD 设置**。全语料 24 篇里，报告了经典长程色散
校正的是 0 篇，所以 `dispersion_correction` 的 `missing 24/24` 是**正确的**。
唯一保留的改动是收紧上面第 6 条那个过泛的键。

## 二轮：标注 24 篇，度量召回率

第一轮只做了**单侧**排查（找假阳性），因此**召回率完全未知**，
一个"什么都不报"的检查器能在那轮拿满分。第二轮补上这一半。

**语料**：24 篇方法段（level 1 完整章节 16 篇 + level 2 子章节 8 篇），
18 字段 × 24 篇 = **432 个判定**。分两批标注，每批 12 篇，协议完全相同。

**标注的独立性**：标注员只看得到方法段原文与由 schema 生成的字段说明，
看不到 `src/`。否则标注会被被测的实现污染，那是自证。

**但标注员是模型，不是人，这一点必须写明。** 两批的落盘时间分别是
**88 秒与 155 秒**（各 12 份文件、各 216 个字段判定），不可能是手工完成：
每篇一个独立上下文的子代理，彼此不可见，也看不到其它论文的标注。
"人工标注"与"模型标注"是两种不同的测量：前者是**外部**金标准，后者
**与被测工具同源**。协议上能隔断的都隔断了（看不到实现、看不到彼此），
但"同一个模型既写工具又当标注员"这一层隔不断，存在同源偏置的可能。
这条记在这里，不藏在脚注里。

**指标**（`python eval/real/score_real.py [--adjudicated]`）：

| 指标 | 全 24 篇，原始 | 全 24 篇，裁定后 | 批一裁定后 | 批二裁定后 | 压假阳性后（原始） | 压假阳性后（裁定） |
|---|---|---|---|---|---|---|
| 状态一致率 | 66.4% | 69.7% | **75.9%** | 63.4% | **75.9%** | **79.2%** |
| 四态宏平均 F1 | 0.580 | 0.651 | **0.718** | 0.570 | **0.716** | **0.770** |
| 取值一致率 | 85.9% (n=64) | 85.9% | 85.7% | 86.1% | **74.7% (n=87)** | 74.7% |

最后两列是"压 `missing` 假阳性"那一轮之后的数（该轮分四层做：打通力场的
能力表与报告表、给 `ambiguous` 补上"部分证据"路径、扩抽取器召回、修正三条
适用性闸门；账本逐层留痕，40 fixed / 1 broken / 5 neutral / 1 disputed）。
**状态一致率涨了 9 个百分点，取值一致率掉了 11 个**，详见下文
「压 `missing` 假阳性」一节，那是这一轮真实的代价。这两列已经含了随后的
第四轮（"取值必须来自正确的指称对象"，2 fixed / 0 broken，见下节）——
所以它们与 `python eval/real/score_real.py [--adjudicated]` 现在跑出来的
数**逐位相同**，而它们左边的四列是历史快照，重跑对不上是预期的。
（`批一裁定后` 与 `压假阳性后（原始）` 同为 75.9% 是巧合，宏平均 F1 不同：
0.718 vs 0.716。）

批一 = 2026-09-25 落盘的 12 篇，批二 = 2026-09-30 落盘的 12 篇（界线是
`make_adjudication_sheet.py` 的 `BATCH1`，与 `_label_work/out/` 的文件时间
一致）。批一先标先裁，批二是后补的。两批都裁完了，24 篇现已全部有裁定。

逐类（24 篇，池化，n 为标注中该类出现的次数）：

| 状态 | 原始 P | 原始 R | 原始 F1 | 裁定后 P | 裁定后 R | 裁定后 F1 | 本轮 P | 本轮 R | 本轮 F1 | n |
|---|---|---|---|---|---|---|---|---|---|---|
| `present` | 0.82 | 0.60 | 0.70 | 0.91 | 0.64 | 0.75 | 0.87 | 0.82 | 0.84 | 106 |
| `missing` | **0.46** | 0.87 | 0.60 | **0.47** | 0.87 | 0.61 | 0.60 | 0.86 | 0.70 | 100 |
| `ambiguous` | 0.53 | **0.13** | 0.21 | 0.78 | **0.29** | 0.42 | 0.65 | 0.38 | 0.48 | 63 |
| `not_applicable` | 0.86 | 0.79 | 0.82 | 0.87 | 0.79 | 0.83 | 0.87 | 0.80 | 0.83 | 163 |

「本轮」三列是**未加裁定**的，与「原始」三列同口径，可直接对比。
注意 `present` 与 `not_applicable` 两行的 P/R 也都动了（`present` 召回
0.60 → 0.82 最明显），不是"没碰"，本轮只承诺不让格子**离开**这两个状态，
而从 `missing` **进入**这两个状态正是要修的方向（47 格变动里 46 格兑现，
唯一例外见下节）。`missing` 的精确率仍只有 0.60：报出的缺失里还有四成是错的。
（「本轮」列是**到第四轮为止**的数，因此 `present` 的 P 是 0.87、`ambiguous`
的三个数是 0.65 / 0.38 / 0.48；第三轮单独结算时的对应值是 0.85 与
0.63 / 0.35 / 0.45。两处差都来自第四轮那 2 格，见下节。）

**为什么两个数都报。** 原始一致率把每处分歧都算作工具的错，而定标人会错。
145 处分歧逐条复核后判出 **14 条标注员错**（多是把"字段状态"与"规则层
严重度"混为一谈，如 PME 未给 rcoulomb）、131 条工具错。裁定会把这一部分
分歧翻成"一致"，所以原始终值是**下限**，裁定后的值是**带裁定意见的上限**，
**真实值在两者之间**。

按批拆开是这样，两批的构成差别很大：

| | 分歧 | 标注员错 | 工具错 | 一致率（原始 → 裁定后） |
|---|---|---|---|---|
| 批一（09-25） | 64 | 12 | 52 | 70.4% → **75.9%** |
| 批二（09-30） | 81 | 2 | 79 | 62.5% → 63.4% |

裁定人即工具作者，**天然偏向自己的工具**，所以上表的裁定后数字应读作
**带裁定意见的上限**，引用时须说明。

另外，`--adjudicated` 只在分歧上生效，**不会**把工具"蒙对"的地方减分，
也就是说裁定只可能抬高分数，不可能压低。这是这套方法的固有偏置，不是 bug。

### 加样本之后：一个方法论上要拆开的混淆

24 篇的总一致率（66.4%）低于批一的 70.4%，看着像"新样本更难"。
**这个读法要拆开才成立，差异主要来自章节层级的构成：**

| 原始一致率 | level 1 完整章节 | level 2 子章节 |
|---|---|---|
| 批一（09-25） | 6 篇，65.7% | 6 篇，75.0% |
| 批二（09-30） | 10 篇，63.3% | 2 篇，58.3% |
| 全 24 篇 | 16 篇，64.2% | 8 篇，70.8% |

批二多抽了 4 篇完整章节，而完整章节本来就难；同一层级内两批的差距
（level 1：65.7% vs 63.3%）远小于总体差距（70.4% vs 62.5%）。
**但"几乎一致"这个说法现在不成立了**，level 1 上仍差 2.4 个百分点，
level 2 上批二只有 2 篇、样本太小，不足以支撑结论。加样本时最容易
被误读成"结论变了"的地方就在这里：变的有样本构成，也可能有别的。

**子章节比完整章节更准这个与直觉相反的现象，24 篇上仍然成立，
但压假阳性之后差距缩到 1 个百分点以内**（原始 76.4% vs 75.0%，
裁定后 79.2% vs 78.5%；压之前是 70.8% vs 64.2%）。原先的担心是"子章节会
漏掉正文别处写过的内容"，在两批合计 24 篇上都不成立，子章节更聚焦，
参数字密度更高。压假阳性那一轮的收益主要落在完整章节上（level 1 涨 10.8
个百分点，level 2 涨 5.6），把两者的差距抹平了大半：**原先的差距里，
有一部分其实来自完整章节里的漏抽更多，与"章节层级"无关。**

### 主要短板（24 篇上更清楚了）

**工具倾向于多报缺失，这与设计目标直接冲突。** 设计原则写的是
"宁可漏报不可误报"，二轮实测 `missing` 精确率 **0.46**（裁定后 0.47），
报出的缺失里一多半是错的，方向与原则相反。裁定几乎不动它：这个短板
**不是**定标口径造成的，是工具真在往这个方向错。

压假阳性那一轮把它抬到 **0.60**（裁定后 0.61），**仍未达标**，
报出的缺失里还有四成是错的。0.60 是这一轮的下限，不是终点。

145 处分歧里 **103 处是"工具报 missing 而标注不是 missing"**，再拆：

| 标注真值 | 二轮 | 压假阳性后 | 含义 |
|---|---|---|---|
| `not_applicable` | 34 | 31 | 该体系根本没有这个字段 |
| `ambiguous` | 38 | 24 | 提到了但不足以行动 |
| `present` | 31 | **3** | 写了，工具没读到 |
| （分歧总数 / 一致率） | 145 / 66.4% | **104 / 75.9%** | |

三行里 **`present` 那行从 31 掉到 3** 是最干净的战果：全部由"扩召回"
那一层拿下，一个字符的 ambiguous 都没用。`ambiguous` 那行 38 → 24 靠的是
新增的"部分证据"路径。`not_applicable` 那行只挪动了 3 处（34 → 31），
**残留最多、进展最小，是下一轮该主攻的方向**。

`not_applicable` 这一行的 31 例里，`constraints` 6、`electrostatics` 5、
`dispersion_correction` 4 共 15 例仍集中在依赖势函数类别的三个字段上
（二轮时是 7 / 5 / 5 共 17 例，其余字段逐项一模一样：`thermostat` 4、
`force_field` 3、`ligand_parameters` 2、`correlation_window` 2 …）。
本文档"这一轮暴露并修掉的缺陷"里那张势函数能力表（`FF_FAMILIES`）在二轮
把这一行从 55 压到 34，本轮只再压掉 3 处（其中 1 处是 `protonation_state`
的封端肽闸门），说明**剩下的问题在于表本身的判据在这些篇章
上落不了地**，与表的宽度无关（例如粗粒化力场 Martini、靠文献转引的势）。按本项目的规则
（"无法 confidently 断言的一律不加"），这几处记录在案、不猜。

`ambiguous` 召回率是另一个独立的短板。二轮原始 0.13：63 个标注为 ambiguous
的判定里，工具只有 8 个也报 ambiguous，其余 38 个报 missing、12 个报
present。压假阳性后升到 **0.35**（裁定后 0.51），这一轮是工具**真的**
多说了"不确定"（部分证据路径），不再是靠裁定抬高的。其后一轮的
"原子数归属"修复又补回 2 格，**0.38**（裁定后 0.54）。但 0.38 仍意味着
**六成多的"提到了但不够具体"，工具还是当成"没写"或"写了"**。

**这一轮也新开了两个口子，必须一起报。** 混淆对 `present → ambiguous`
从 6 涨到 **11**，部分证据路径在标注员判 `present` 的格子上也开火了，
这 5 格是账本里的 **neutral**（旧错新错，gold 一直是 `present`），
正确修法是补这些格子的召回，不是把部分证据收窄；`ambiguous → present`
从 12 涨到 13（其后一轮把这一对压回 11，见下）。**净效果是赚的
（分歧 145 → 106），但这两个数不能藏。**

### 压 `missing` 假阳性（第三轮）

**起点与目标。** 二轮结束时状态一致率 66.4%（裁定后 69.7%），但 `missing`
精确率只有 **0.46**，设计原则写的是"宁可漏报不可误报"，实测方向恰好相反。
145 处分歧里 103 处是"工具报 missing 而标注不是"，按标注真值拆开，
三类的**修法完全不同**：

| gold | 处数 | 性质 | 该动哪一层 |
|---|---|---|---|
| `present` | 31 | 写了，工具真没读到 | **召回层**（补词汇） |
| `ambiguous` | 38 | 提到了，但不够具体 | **部分证据层**（工具根本没有这条路径） |
| `not_applicable` | 34 | 该体系没这个字段 | **适用性层**（闸门判错） |

目标：`missing` 精确率 **→ 0.60**，且 **`broken == 0`**。
**第一个目标达到了，第二个差 1 格**，按事先定好的规矩，那一格不靠收窄
正则去凑，而是原样留下、上报（见下）。

**账本协议先于改动。** 新增 `eval/real/status_diff.py`：每次改动前后各拍一张
逐格快照，把**每一个变动的格子**对着标注判成 `fixed` / `broken` / `neutral` /
`disputed`（定义见该文件与 `--help`；**判据是对着标注，不是对着上一次运行**）。
硬约束逐项打印，任一不成立即非零退出：ctx 未漂移、规则编号未漂移、
状态与取值自洽、同一棵树连跑两次一致、快照未过期、未离开 `present` /
`not_applicable`。
**`neutral`（旧错新错）必须逐格打印、不许折叠**，指标不动不等于没发生变化，
它可能只是换了一种错法。这条纪律在下面救了两次。

**四层分别过账本，逐层停：**

| 层 | 做什么 | fixed | broken | neutral | disputed |
|---|---|---|---|---|---|
| 甲 结构层 | 力场能力表与报告表打通；重音分裂修复；恒温器/恒压器/系综的"注释写了、代码没写" | 9 | 0 | 0 | **1** |
| 乙-1 部分证据层 | 给 `ambiguous` 补上"有证据但不足"这条路径（`missing → ambiguous`） | 9 | **1** | 4 | 0 |
| 乙-2 召回层 | 补抽取器词汇（`missing → present`） | 19 | 0 | 1 | 0 |
| 丙 适用性层 | 三条判错的闸门（色散/键约束/可滴定基团） | 3 | 0 | 0 | 0 |
| **合计** | | **40** | **1** | **5** | **1** |

**结果（24 篇，原始口径）：**

| | 二轮 | 本轮 | 本轮（裁定后） |
|---|---|---|---|
| 状态一致率 | 66.4% | **75.9%** | **79.2%** |
| 四态宏平均 F1 | 0.580 | **0.716** | **0.770** |
| `missing` 精确率 | 0.46 | **0.60** | 0.61 |
| `ambiguous` 召回率 | 0.13 | **0.38** | 0.54 |
| 取值一致率 | 85.9% (n=64) | **74.7% (n=87)** | 74.7% |

**这一轮的代价必须一起报：取值一致率掉了 11 个百分点。** 分母从 64 涨到
87（新可比 23 格，无 1 格离开），正确数从 55 涨到 65，**新召回的 23 格里
只有 10 格取值是对的（43.5%）**，`initial_structure` 的 4 格**全错**。
这正是本项目反复强调的"缺失会被看见，错值不会"：多报一个 present 而取值错，
比报 missing 更糟。**下一轮的主攻方向在这里，不在状态一致率。**

**账本抓到的两个必须上报的结果：**

1. **1 处 `broken`：** `1007.5359v2|ensemble` 由 `missing` 变 `ambiguous`，
   而标注是 `missing`。这是"给系综加泛化写法 + 歧义规则"顺手带出来的，
   不是本轮目标的方向。
2. **1 处 `disputed`：** `1007.5359v2|thermostat`，该格二轮已裁定为
   `annotator_wrong`（标注错）。工具改了之后**基准不复存在**，算 `fixed`
   是自我表扬，算 `broken` 是循环论证。**这一格连同上面那格，都要人来定**，
   两件的证据都在下面。

另需如实记一笔：本轮承诺"只可能让格子**离开 `missing`**"，47 格里 **46 格
兑现**，唯一的例外是 `1007.5359v2|temperature_bath`（`not_applicable →
ambiguous`）。它由 `nemd` 闸门补上"两端热浴"写法引起，且新状态**正是标注的
答案**（gold=`ambiguous`），方向是对的，但它确实离开了 `not_applicable`，
所以全轮对账加 `--strict-containment` 会退出码 2。**逐层看，丙那一层
（`yb2f → yb3d`）是 3 fixed / 0 broken / 0 neutral，加 `--strict-containment`
仍然退出码 0。**

**取值层单独对账：** `_scratch/value_diff.py` 与状态账本分开跑。状态没动、
取值被悄悄换掉，在状态账本上完全隐形，对使用者却是实打实的错值。本轮
**被改写的格子 0 个**，26 处取值变动全部是从无到有（`missing → present`
的必然产物）。

#### 两个悬而未决的判定（都在 `1007.5359v2` 上）

**（一）`thermostat`：规范要求"类型**与**耦合常数"，工具只给类型。**
`spec.md` 把这个字段定义为恒温器的**类型与耦合常数**两部分。实测：语料里
"只给类型、没给耦合"的格子共 9 处，其中 **5 处标注为 `ambiguous`**
（规范说得通），**4 处标注为 `present`**，而那 4 处的正文里**确实写了
耦合常数**，是工具的召回没抓到。所以正确的修法是**两步**：先补上那 4 处的
耦合常数抽取，**再**把剩下的降级为 `ambiguous`。只做第二步会是
**+5 fixed / −4 broken**，净亏。**本轮两步都没做**，先做第一步才谈得上第二步。

**（二）`ensemble`：同一种证据，标注给了两种答案。**
"全文只提到恒温器、没声明系综"这个证据形态，语料里出现在 4 篇上：
3 篇标注为 `ambiguous`，**1 篇（`1007.5359v2`）标注为 `missing`**。
工具现在按 `ambiguous` 处理，于是那 3 篇一致、这 1 篇成 `broken`。
**建议裁定 `1007.5359v2|ensemble` 为 `annotator_wrong`**（同一证据形态
不该有两种答案，而 3:1 多数在 `ambiguous` 一侧，也与规范对"提到了但不够
具体"的定义相符）。**若反过来从严处理**（把闸门收窄，只在写明了系综词时
才判 `ambiguous`），代价是 **2 fixed → 2 broken**，实测净亏。

两条都属于"判据本身有分歧"而非"实现有 bug"，**交人裁定，工具不自行改判据**。

#### 量了但**不做**的四处

本项目的规则是「**无法 confidently 断言的一律不加**」「**'更讲道理'不是判据，
量出来的才是**」。下面四处都量和过，都否决了，理由各不相同：

| 候选 | 实测 | 结论 |
|---|---|---|
| `LIGAND_RE` 去掉 `small molecules` | **2 fixed / 2 broken** | 净 0，不做 |
| `2409.15478v1`（Martini 粗粒化）→ `constraints` 判 N/A | 无法坐实 | 不做 |
| `2506.04835v1` → `correlation_window` 判 N/A | 1 fixed / 0 broken，**但会误伤** | 不做 |
| `2108.03424v1` → `dispersion_correction`（文献转引） | 无法坐实 | 不做 |

**`small molecules` 这条值得展开，因为它差点混过去。** 去掉它能让
`1002.0354v1` 与 `2404.14338v1` 各修好一格（gold 都是 `not_applicable`），
但会让 `2602.17595v1`（gold `present`）和 `2604.01940v3`（gold `ambiguous`）
变错。逐条看那四处的命中句，`small molecules` **四次都不是"体系含配体"**：

| 篇 | 命中句 | 它其实在说什么 |
|---|---|---|
| `1002.0354v1` | "acid-base reactions of small molecules" | **未来工作**（"not yet implemented"） |
| `2404.14338v1` | "the group of small molecules contains two structures: …" | 体系自身的物种，不是配体 |
| `2602.17595v1` | "the small molecules into polymers (SmiPoly) dataset" | **数据集名** |
| `2604.01940v3` | "CGENFF for small molecules and the TIP3P water model" | **力场适用范围** |

也就是说 `2602.17595v1` 那格**修对了，但理由全错**，答案挂在一个假闸门上。
这正是账本要盯的东西：**`fixed` 也可能是蒙对的**。四种误命中形态各不相同，
没有一条"邻近参数化语境"的规则能同时挡住四者又不误伤，所以**不收窄**。

**`2506.04835v1` 这条的否决最有价值。** 可实现的那条代理判据是
"`heat_transport=True` 且全文没有热流词汇 → `correlation_window` 判不适用"，
实测 **1 fixed / 0 broken**，表面完全合格。但它错得很隐蔽：`1007.5359v2`
在这条判据下词汇数也是 0，会被判成"本文不算热流"，而那篇正文里明明白白
有 25 处 thermal conductivity、κ 随长度的线性增长、弹道输运区判定。
词汇数为 0 的真实含义是"**我们手上这段节选没用这些词**"，不是"没做这个计算"。
按账本它会被记成 `neutral` 而不是 `broken` 蒙混过关，**"neutral 必须打印、
不许折叠"这条纪律就是为了拦住这种情况**。

### 取值必须来自正确的指称对象（第四轮）

第三轮把 `missing` 压下去之后，取值一致率掉到 74.7%，主攻方向转到取值质量。
这一轮只做一件事，但它是本项目最怕的那一类错：**值的格式完全正确，
却指错了对象**。

| # | 现象 | 性质 | 修法 |
|---|---|---|---|
| 30 | 抽取器只认裸模式 `<数字> atoms`，不问这个数属于谁：`2207.13405` 的 "914 structures with 54840 atoms in total" 是 NEP 势**训练集**的规模，被填进"体系规模"；`2602.17595v1` 的 "each chain ... approximately 200 atoms" 是**化学表示（SMILES）里单条链**的规模，同样被填进去 | **取值错误（指称对象错）** | 新增 `_SIZE_OTHER_REFERENT` 否决表：训练集/数据集、化学表示/描述符、"N 个结构共 M 个原子"、单条链/单体。命中即**跳过该候选继续往后找**，而不是放弃整个字段 |

它不是召回问题：两处都"读到了"数字，只是读错了这个数字在讲谁。
**这比漏读危险得多**——漏读会在检查单上留一个"未报告"，而错值会在检查单上
写着一个看起来很具体的数，读者没有任何线索去怀疑它。语料里 `<数字> atoms`
（三位以上）一共 4 处，2 处是真正的模拟胞（1728、8640，均出自 `1805.00269v1`），
2 处是这里修掉的错指称对象。

改动只有 2 格，账本 `status_diff.py --diff yb3d referent_fix`：
**2 格变动 = 2 修复 / 0 破化 / 0 中性 / 0 待裁定**，全语料 432 格里只有这 2 格动。

| 格子 | 改前 | 改后 | 标注 |
|---|---|---|---|
| `2207.13405` / `system_size` | `present` `{"atoms": 54840}` | `ambiguous` `{"box_nm": 13.3}` | `ambiguous` ✓ |
| `2602.17595v1` / `system_size` | `present` `{"atoms": 200}` | `ambiguous` | `ambiguous` ✓ |

两处对应的裁定（均为 `tool_wrong`）随之退役——它们所针对的分歧已经不存在了。
全量分数：24 篇原始 **75.5% → 75.9%**（宏平均 F1 0.706 → 0.716），裁定后
**78.7% → 79.2%**（0.762 → 0.770）；`ambiguous` 召回 **0.35 → 0.38**
（裁定后 0.51 → 0.54）；`missing` 精确率 0.60 不变。18 篇域内：原始
81.5% → **82.1%**，裁定后 85.8% → **86.4%**。

**这一轮顺带自证了本项目的核心命题。** 修好之后 `2207.13405` 的检查单上
多出一行 `R-05 热输运计算未报告体系尺寸：无法评估有限尺寸效应`——那个假的具体
值此前一直在**让这条警告闭嘴**：填一个假值，反而不报缺失了。
"缺失会被看见，错值不会"在这里不是一句口号，是一次可复现的对照。

两处边界一并记下（都不改，留着）：

- **`R-05` 的话术比判据宽。** 这篇确实报了盒子尺寸（`W=13.3 nm`），只是没报
  原子数，而 `R-05` 的话说成"未报告体系尺寸"。`ambiguous` 与 `missing` 在
  `_present()` 眼里同属"未确立取值"，警告照发。拆成"无尺寸"与"尺寸不完整"
  两条会移动更多格子，本轮不动。
- **`1805.00269v1` 一篇报了两个被模拟的体系**（体硅 EMD 的 N=1728、硅烯 EMD 的
  N=8640），都是真模拟胞，抽取器只取第一个。这是"只报了一个指称对象"，
  不是"取错指称对象"，性质较轻，明确记为已知开口。

**保守上的一处自律**：`_SYS_BOX_RE` 的宽度是**量出来的**——它的注释记着
"宽版本实测 6 fixed / 3 broken，'宁可窄'是量出来的，不是猜的"。所以这一轮
**没有去放宽它**，而是扩了**抽取器**：先遍历候选、跳过被否决的，再补一条
带等号的符号式尺寸模式（`W=13.3 nm`，二维材料几乎只写这一种），后者用
`not m` 守住——已经有原子数时不去别处凑一个尺寸，凑来的多半属于另一个子体系。
该模式的实测影响面是**1 篇**（`2207.13405`）。两处都已固化为回归测试第 25 组。

按 README 前面「章节切分把不在主题内的论文收了进来」的定义，24 篇里

读者请自行减掉这 44%。

### 刻意不做的边界

非经典势（ReaxFF / Brenner / Tersoff / 粗粒化 / 机器学习势）下，
电静力、键约束、色散校正是否适用**取决于势函数类别**。这曾是语料中最大的一类
分歧（24 篇上 55 例 NA→missing，见「主要短板」）。

**这张表已经实现了**（`FF_FAMILIES`，能力表的每一族带 `pattern` / `names` /
`bonds` / `coulomb` / `dispersion` 五项，多族命中时逐项取 **AND**），它把
NA→missing 从 55 例压到 34 例、第三轮再压到 31 例。之所以敢实现，是因为
它只在**文本确实点名了某个势**时才生效，表里没写到的势一律回落到"全都
适用"的默认，不会去猜。

**仍然刻意不做的是更激进的版本**：靠"这是粗粒化体系 / 这是反应体系"这类
间接信号去推定整族字段不适用。实测的四条候选（Martini 粗粒化、文献转引的
势、`small molecules` 当配体、热流词汇计数当闸门）全部否决，逐条实测见
「压 `missing` 假阳性」一节的"量了但不做的四处"。

### 语料本身的四个已知缺陷（不是工具的缺陷）

**一、希腊字母被 LaTeX 清理吞掉。** `fetch_arxiv.py` 的 `strip_latex` 里，
数学模式的内容是**保留**的（数值常在公式里），但随后的符号替换表没有任何
希腊字母，最后一步"删未知命令保参数"于是把它们连参数一起抹掉：

| 原文 | 语料里 | 后果 |
|---|---|---|
| `$\mu$m` | `m` | 长度量纲丢失，`82 nm to 1 m` |
| `$\alpha$-cristobalite` | `-cristobalite` | 物相名残缺 |
| `$\Gamma$-point` | `-point` | 高对称点残缺 |
| `$\tau$` | （空） | 变量名下划线错位成 `_T` |

全语料 `μ` 出现 **0 次**、`\mu` 残留 **0 处**，是系统性的，不是个别。
修法是一行：在替换表里补上 `\mu` `\alpha` `\beta` `\gamma` `\Gamma`
`\tau` `\sigma` `\epsilon` `\rho` `\Delta` 等。**本轮没有回补**，
因为 24 篇标注都是照现有语料判的，回补会让全部标注失效。

**二、重音字母被拆散。** 同一张符号替换表把 `é`/`ñ` 一类字符拆成
撇号加字母，专有名词因此对不上：

| 原文 | 语料里 | 后果 |
|---|---|---|
| `Nosé-Hoover` | `Nos ' e -Hoover` | 恒温器名认不出 |

`1805.00269v1` 的 `thermostat` 分歧就是这条造成的：正文用 NEMD 冷热源、
明写 Nosé-Hoover chain，而工具在 `Nos ' e -Hoover` 上匹配失败，判了 missing。
**这一例要记在语料账上，不是工具的判据错。**

**三、数学模式里的时间单位被整体丢掉。** `2604.01940v3` 的方法段里
` fs` / ` ns` / ` ps` 出现 **0 次**，而 ` K ` 这类不在数学模式里的单位
完整保留：

| 原文 | 语料里 | 后果 |
|---|---|---|
| `time step of $2$ fs` | `time step of 2` | 数值在、单位没了 |
| `$t^*=4.66\cdot 10^{-3}$` | `t^ * =4.66. 10^ -3` | 指数被拆散，工具只读到 `4.66` |

两条后果不同：前者让工具"有数无单位"而降级为 `ambiguous`（标注按原文
判 `present`），后者让工具读出一个**错了一千倍**的时间步。这类损伤
对**数值型字段**的取值一致率影响最大，而取值的错是最难被使用者发现的一类。

**四、章节切分把不在主题内的论文收了进来。** `is_md_paper()` 是词汇判据，
会把"像 MD"的非 MD 论文放进语料：

- `1603.06347v2` 是**强子气体状态方程**，全篇没有 MD 时间积分，却因含
  热输运词汇通过筛选，一篇贡献了 11 处分歧；
- `2404.14338v1` 是 **ReaxFF 参数化**论文，方法段里没有时间积分；
- `nlin/0210052v1` 是**恒温驱动振子**的 Lyapunov 谱分析，不是分子体系；
- 另有 `cond-mat/9910397v1`（LJ 氩热扩散）、`2108.03424v1`（一维 FPUT
  晶格）、`cond-mat/0701254v1`（有限力程粒子模型）三篇**是 MD 但不在
  目标域内**（非生物/软物质 MD）。

**这 6 篇在二轮合计贡献 49/145 = 34% 的分歧，第三轮后是 46/104 = 44%**
（这 6 篇几乎没动，是分母变小了）。剔除后 18 篇的一致率：原始 82.1% /
宏平均 F1 0.780，裁定后 **86.4% / 0.842**（对照 24 篇的 75.9% / 79.2%）。
详见上文「语料侧的干扰」一节。

为什么这不使指标失去意义：**工具与标注员读的是同一份文本**，共同的语料缺陷
对两边同等作用，不产生系统性偏向。它损害的是**可推广性**（换个语料，
`system_size` 这类跟数值相关的字段表现可能不同），不是**有效性**。
唯一要防的是：标注员**修复**了语料损伤而工具没修复时，会凭空多出一处分歧。
`1805.00269v1`（`82 nm to 1 m`）与 `1002.0354v1`（`-cristobalite`）的
`system_size` / `protonation_state` 分歧就属于这一类，裁定时要先扣掉。

这些篇目的多数判定本应落 `not_applicable`，是**工具设计范围之外**的输入。
它们拉低的是总分，但拉低的方式说明的是语料筛选问题，不是抽取问题，
**报告聚合数字时要么剔除，要么分层，不能混在一起当成工具的错**。

### 方法上的一条：裁定会过期

`adjudication.json` 里的裁定是针对**某一次具体分歧**做的判断，不是对字段的
永久判决。工具一改版，被裁定的那一对可能已经一致；此时留着旧裁定
**会对一个已不存在的分歧罚分**（方向无所谓，错的是逻辑）。
`score_real.py` 因此显式作废这类"悬空裁定"并**计数上报**，不静默丢弃，
静默丢弃与静默罚分一样，都会让指标对不上账。
