# md-repro-checker

**MD 方法段可复现性检查器**，从文献的方法段出发，检查它是否足以复现，
生成带来源标注的输入文件，判定模拟结果是否可信，并回答
**一组文献报告的同一个量彼此是否可比**。

> 追光计划第二期 · 线上实习申请 Demo
> 全部结果可一条命令复现：`python run_demo.py`

---

## 它解决什么问题

分子模拟的复现失败，绝大多数不在代码层面。代码、力场、软件都是公开的，
但**把一篇文献的方法段变成一份能跑出同样数字的输入文件**仍然高度依赖人力。

```
$ python -m src.cli examples/case-01/methods_v1_typical.txt

可复现性评分  : 28 / 100   [等级 D]
  严重 1 · 一致性 7 · 缺失 3 · 歧义 0 · 影响归因 3

【一致性冲突】
!  [R-02] 报告了恒压器类型但未给耦合常数 tau_p：压力耦合强度不可复现
!! [R-03] 热输运计算未报告统计窗口/关联时间：无法判断 κ 是否取自平台区
!  [R-05] 热输运计算未报告体系尺寸：无法评估有限尺寸效应
!  [R-08] 报告了模拟时长但未说明重复次数：统计误差无法评估
!  [R-10] 使用 PME 但未给出实空间截断半径 rcoulomb
!  [R-11] NEMD 冷热浴温差相对平均温度超过 10%：可能已偏离线性响应区，此时 κ 依赖于 ΔT 本身，不再是材料常数
!  [R-12] 报告了恒温器类型但未给耦合常数 tau_t：恒温强度不可复现，对扩散/热导/粘度等输运性质可造成 10-30% 偏差
```

（`!` 为 important，`!!` 为 critical）

同一个研究补全后：

```
$ python -m src.cli examples/case-01/methods_v2_complete.txt
可复现性评分  : 100 / 100   [等级 A]
```

**一个只会报警的检查器没有价值。** 工具必须能在方法段达标时明确闭嘴，
否则使用者无法用它判断"改好了没有"。

---

## 两个核心判断

**1. "文献没写"与"本文体系不存在这个问题"必须区分**

二者的数据表现完全相同（字段为空），含义却相反。干态聚合物熔体
没有"水模型"可言，报它缺失就是假阳性，而假阳性是使用者放弃工具的首要原因。

因此输出用**四态**而非二态：

| status | 含义 |
|---|---|
| `present` | 明确报告 |
| `missing` | 该写没写，缺陷 |
| `ambiguous` | 写了但有歧义（如只写 "AMBER" 不给版本） |
| `not_applicable` | 本文体系里不存在这个问题 |

**2. 取值错误比字段缺失更危险**

缺失会被看见，错值不会，它会被当作事实使用。开发中实际出现过两个：
`cold_K=30`（抓到了 ΔT 扫描点）、`replicas=30`（抓到了 "30 repeat units"）。
两个都"看起来合理"。因此评估指标里**取值准确率单独统计**。

## 它比通用文献解析工具多了什么

```
schema/md_method.yaml      每个字段"是什么、为什么重要"（18 字段分三级）

schema/sensitivity.yaml    在"这个具体场景下"，缺失会让结果偏多少
                           when {heat_transport: true} 才触发
```

同样一个 `thermostat` 字段缺失：

- 算结合自由能 → 无关紧要
- 算热导率 → Berendsen 恒温器压制涨落，κ 被系统性低估 10-30%，结论不可用

通用解析器能告诉你 `thermostat: missing`。
只有懂 MD 的人能告诉你"因为你在算热导率，所以这一条让结论直接不可用"。

**这就是本 Demo 的增量。**

## 五段流水线

| 模块 | 职责 | 依赖 |
|---|---|---|
| `src/extract.py` | 方法段 → 四态结构化字段（schema 的 18 字段全部由规则覆盖） | pyyaml |
| `src/validate.py` | 一致性检查、场景敏感性归因、评分 | pyyaml |
| `src/build_inputs.py` | 生成 .mdp / .lmp / OpenMM 骨架 + **逐参数来源标注** | 纯标准库 |
| `src/convergence.py` | Green-Kubo / NEMD 结果有效性判定（A/B/C/D） | 纯标准库 |
| `src/corpus.py` | 成组文献的**横向可比性**：一组报告的同一个量，彼此可比吗 | pyyaml |

规则与 LLM 的分工是**能规则化的绝不下放**：早期版本把 `software`、
`initial_structure` 也交给 LLM，实测完全可以正则化，且规则的精确率更高、
零成本。目前只有 `missing_residues_note` 这类真正需要读句子语义的开放描述
才走 LLM，且该字段不在 schema 的 18 字段之内。

五段松耦合，每段可单独调用，真实场景里多数使用者只需要其中一段。
第五段与前四段的**分析单元不同**：前四段问"这一篇够不够复现"，
第五段问"这一组文献报告的同一个量，彼此可比吗"（见下）。

### 输入生成的来源标注

这是 `build_inputs.py` 存在的理由：

```
  统计 (GROMACS): paper 5 · default 11 · builtin 15
  统计 (LAMMPS):  paper 7 · default  8 · builtin 14

  以下参数原研究未报告，由工具填入默认值：
      DispCorr, rcoulomb, rvdw, tau-p, tau-t, ...
      → 若要真正复现，这些必须向作者确认，或做敏感性检验。

【无法默认、必须由文献提供的字段】
  !! correlation_window   !! dispersion_correction   !! system_size
  → 这些字段缺失时，生成的输入文件不构成对原研究的复现。
```

一个静默填了默认值的输入文件，跑出来的结果看起来完全正常，
标注出来，使用者才知道哪些结论建立在假设之上。

**两套引擎分开统计。** 同一个物理量在 `.mdp` 与 `.lmp` 里的表达方式与
覆盖面都不同，混在一张表里会让"这个默认值属于哪个引擎"变得不可判断，
而默认值恰恰是最需要被逐一确认的东西。

最后一节的字段由敏感性归因层传入：**判断归知识层，执行归生成器。**

### LAMMPS 生成器的四条硬规则

LAMMPS 与 GROMACS 的差别不在语法，在于**它不会替你兜底**。
以下四条都是"写错了不报错、只是数不对"的地方，生成器因此不肯默认：

| 规则 | 理由 |
|---|---|
| 拒绝伪造力场参数 | LAMMPS 不读力场库。生成 `include TODO.forcefield` 而不是编一套 `pair_coeff`，伪造的力场跑得起来，但跑的不是原来那个体系 |
| PME 必须成对出现 | `pair_style lj/cut/coul/long` 与 `kspace_style pppm` 缺一不可。只写 `coul/cut` 且不给 kspace 时 LAMMPS 不报错，只是静默退化为纯截断库仑 |
| `special_bonds` 挂在力场上 | 1-4 非键缩放是力场定义的一部分，不是可以各阶段各写各的运行参数。挂在力场上，从源头消除"平衡段与生产段用的不是同一个体系" |
| `pair_modify mix` 挂在力场上 | LJ 交叉项混合规则同样由力场族决定，而且**有默认值**：默认 `geometric`（σ 取几何平均），AMBER/GAFF/CHARMM 要的却是 Lorentz-Berthelot（σ 取算术平均），COMPASS/PCFF 要六次方规则，而 **OPLS-AA 用的恰好就是几何平均**。于是同一个"漏写 mix"的动作，对哪一族有害取决于力场族——判据不能按"这一行在不在"来定。漏写不报错、不警告，只是所有 I≠J 交叉对的 σ 系统性偏移 |

最后一条值得单独说明，因为它是本项目"静默失效"论点的最纯粹样本：
LAMMPS 源码 `src/pair.cpp` 的 `mix_energy()` 在 `geometric` 与 `arithmetic`
下**返回同一个值** `sqrt(eps1*eps2)`，只有 `mix_distance()` 不同，
**ε 完全不受影响，只有 σ 变**。于是能量项上看不出任何异常，
而交叉对的作用距离已经偏了。

这个偏差的大小不用测也能定：由 AM-GM 不等式，算术平均恒 ≥ 几何平均，
两者之差随 **σ_i 与 σ_j 的差距**单调增大，所以轻原子与重原子配对时最明显，
同类原子之间则完全无差别（此时两规则给出同一个 σ）。
换句话说，**错得最厉害的地方恰好是最不容易被注意到的地方**。

日志里 LAMMPS 会打印 `Generated N of M mixed pair_coeff terms from X mixing rule`，
这是自查实际生效规则的唯一线索，但前提是你知道要去看。

`DREIDING` **刻意不在映射表里**：它的混合规则未能坐实，与其猜一个值写进去，
不如落到 TODO 分支。这与"拒绝伪造力场参数"是同一条原则，
**不确定时留空比填错更安全**，因为填错的值不会被看见。

热输运段另外处理三个反直觉点：

1. **恒温 `fix` 的 group 不能写 `all`。** `fix langevin` 的受力范围由
   **fix 自己的 group** 决定，不是由 `fix_modify temp` 指定的 compute 的
   group 决定（源码 `fix_langevin.cpp` 的 `if (mask[i] & groupbit)`）。
   两个恒温器都写 `all` 时，全体原子被两个不同温度的浴同时作用，
   温度梯度被抹平，脚本正常运行，κ 无意义。
2. **热流用 `centroid/stress/atom` 而非 `stress/atom`。** 手册明确警告后者
   对 angle / dihedral / improper / constraint 的贡献会给出非物理值
   （Surblys2019, Boone, Surblys2021）。聚合物体系正好落在这个警告范围内。
3. **归一化体积取测量组所在体积。** `compute heat/flux` 返回的是 extensive 值，
   手册要求除以"包含该 group 原子的体积"。group 是中央切片时用整盒体积
   会算错，且不报错。

这些不是代码风格问题，每条都对应一个人眼容易漏掉、而检查器能稳定发现的
静默错误。`check_lammps()` 因此不只校验命令名与重复 ID，还专门检测
"跑得完但没意义"的脚本。

进**错误**的（脚本一定有问题）：

- **两个恒温 fix 的 group 都是 `all`**，控温范围完全重合，梯度被抹平
- **有 `run` 步数却没有任何积分器 fix**，原子永远不动，
  LAMMPS 不报错、步数跑满、输出文件齐全且数值稳定

第二条是实际开发中真出现过的：文献报告 NPT 时，`nvt` 阶段既没拿到
`fix nvt` 也没拿到 `fix npt`，生成出一份空转脚本。**这类错误靠读代码
很难发现，靠一条检查规则却很容易。**

进**警告**的（能跑，但可能不是你想要的那个物理）：

- **有 `lj/cut` 系 `pair_style` 却没有任何 `pair_modify ... mix`**，
  见上文混合规则一节。它只警告不报错，因为无法从脚本反推力场族，
  而"所有交叉对都由 `pair_coeff` 显式给定"的脚本确实不需要这一行：
  判据不足以断定脚本有问题时，工具只提示、不拦路。

### 检查别人写好的脚本

生成器与检查器共用同一套判据，能发现自己生成的文件里的问题，
也必须能发现别人手写脚本里的同一类问题。独立入口复用同一个位置参数：

```
$ python -m src.cli --check-lammps some_paper_script.lmp

LAMMPS 脚本静态检查
文件    : some_paper_script.lmp
命令数  : 41

【警告】：脚本跑得完，但可能不是你想要的那个物理
  !  有 pair_style lj/cut* 但未声明 pair_modify mix：LAMMPS 会静默采用
     默认的 mix geometric（σ 取几何平均）。若这份脚本用的是 AMBER/GAFF/CHARMM，
     它们要的是 Lorentz-Berthelot（σ 取算术平均），交叉对的作用距离就会偏移；
     COMPASS/PCFF 要六次方规则，同样对不上。但 OPLS-AA 用的就是几何平均，
     对它是正确的——本检查无法从脚本反推力场族，因此只能提示，不能判定为错误。……
```

**只有错误会产生非零退出码**，警告是给人判断的，不该卡住 CI。

### 结果判定不输出裸数值

> 一个未收敛的 κ 和一个收敛的 κ，在数值上无法区分，
> 但在科研决策中的价值截然不同。

```
案例 good                          案例 poor
[J1/J2] 等级 A                     [J1/J2] 等级 D
    κ = 0.0878 ± 0.0010                κ = 0.1581 ± 0.0257
    窗口均值 0.0860 → 0.0881           窗口均值 0.1221 → 0.1846（持续爬升）
综合等级: A                         综合等级: D
该结果可用于定量比较                 该结果不应进入任何数据集
```

`poor` 的 κ 更大，看起来"信号更强"，但它仍在漂移。

### 换一个分析单元：从「一篇」到「一组」

前四段逐篇工作，每篇各出一份检查单。第五段 `src/corpus.py` 把分析单元
换成**一组**，问一个逐篇工具原理上答不出的问题：

> 这一组文献报告的同一个物理量，彼此之间可比吗？

它没有引入新的领域知识，`sensitivity.yaml` 里"未报告恒温器 = 该 κ 值
不可与其他文献横向比较"早就写好了，只是一直被施加在单篇上。这一段的
全部内容是**换个单元把同一套知识重新施加一遍**，因此它没有新增一条
领域判断，却能看到单篇看不到的三类现象：

| 类型 | 含义 | 为什么逐篇看不到 |
|---|---|---|
| **取值分歧** | 同一物理量，不同文献给出不可通约的取值 | 单篇只能各说各的 |
| **报告不全** | 取值一致，但有几篇没报 | 缺失被逐篇平摊掉了 |
| **集体缺失** | 该组**无一篇**报告某关键量 | 每篇都只是"缺一个字段" |

实测 11 篇热输运文献（arXiv，公开）：统计窗口与关联时间 **0/11 篇报告**，
热流计算方法 4 种并存，体系规模仅 1 篇报告，
冷热浴 ΔT 两篇报了却一个 20 K 一个 60 K
→ 结论「不可横向比较」。**`--flag` 换分组即可复用到别的场景**
（`heat_transport` / `protein_present` / `ligand_present` / `explicit_solvent`）。

这一段还抓到过工具自己的一个错值：`system_size` 曾把 `2207.13405` 的
NEP **训练集**规模（54840 atoms）当成被模拟体系的原子数，凭空造出一条
"1728 vs 54840"的假分歧。详见 `docs/demo-note.md` §3.7。

两条刻意的保守设计：

- **没有依据的差异不构成发现。** 只比较 `sensitivity.yaml` 写了影响规则的
  字段。一组文献在 `timestep` 上有 4 种取值，但知识层没为它写规则，不报。
- **字典取值按公共键交集比较。** `{type: Nose-Hoover, coupling: 0.1}` 与
  `{type: Nose-Hoover}` 的交集是 `{type}`，两边同为 Nose-Hoover，
  这是**报告不全**，不是协议分歧。若不取交集，每多一篇少写一个可选键
  就凭空多一条假分歧。

## 评估

`eval/score.py` 在 18 字段 × 2 版本的人工标注上计算四类指标：

```
平均三态宏 F1   1.000
平均取值准确率  100.0%
平均规则 F1     1.000
假阳性总数      0
```

三类指标刻意分开，对应三类失败：状态判错、值抓错、误报。
`labels/case-01.json` 中另有 `rules_forbidden` 列表专门用来抓假阳性，
`R-06`（对干态聚合物熔体误报水模型缺失）就是这样被发现的。

> **合成标注集只有 2 个版本**，能暴露错误类型，不足以给出稳定指标。
> 真实集已扩到 24 段（见下），但要有统计意义仍需 30-50 段。

### 在真实文献上的第二把尺子（`eval/real/`）

合成标注集有一个绕不开的问题：规则在**自己写的**方法段上全对，
只证明规则符合自己的预期。真实文献不那样写。因此在 arXiv 方法段上
另做了一轮，语料因版权不随提交分发（`eval/real/`）。

**独立标注 24 篇真实方法段（432 个判定）**，标注员只看到方法段原文与
由 schema 生成的字段说明，看不到 `src/`、也看不到彼此的标注，
否则标注会被被测的实现污染。**标注员是模型而非人工**（每篇一个独立
上下文的子代理；两批各 12 份文件分别写在 88 秒与 155 秒内，不可能手工完成）。
这一点如实写明：协议能隔断的都隔断了，但"同一个模型既写工具又当标注员"
这一层隔不断，**同源偏置无法排除**。

| 指标 | 24 篇，原始 | 24 篇，裁定后 | 批一裁定后 | 批二裁定后 | 24 篇，压假阳性后 |
|---|---|---|---|---|---|
| 状态一致率 | 66.4% | 69.7% | **75.9%** | 63.4% | **75.9%** |
| 四态宏平均 F1 | 0.580 | 0.651 | **0.718** | 0.570 | **0.716** |
| 取值一致率 | 85.9% (n=64) | 85.9% | 85.7% | 86.1% | **74.7% (n=87)** |

最后一列是"压 `missing` 假阳性"那一轮（甲/乙-1/乙-2/丙四层）之后的数（裁定后为 79.2% /
宏平均 F1 0.770），已含其后的"取值必须来自正确的指称对象"一轮（2 fixed / 0 broken），
**读者跑 `python eval/real/score_real.py` 能复现这两列**；左边的四列是历史快照，
重跑对不上是预期的（`批一裁定后` 与最后一列同为 75.9% 是巧合，宏平均 F1 不同：
0.718 vs 0.716）。**状态一致率涨了 9 个百分点，取值一致率掉了 11 个**，两个
方向相反，必须一起报：该轮把 23 个格子从 `missing` 拉进了 `present`（可比格数
64 → 87），而这些新报出来的 `present` 里取值对错的只有约 **43%**（净增 23 格、
净增 10 个取值正确）。换句话说，**新召回的那批格子，取值质量明显低于原有格子**。
按本项目"缺失会被看见、错值不会"的立场，这是该轮真正的代价，也是下一轮的方向
把已召回格子的取值做准，比继续扩大召回更要紧。

**两个数都要看，不能只报大的那个。** 原始一致率把每一处分歧都算作
工具的错，而定标人会错，压假阳性之后的 104 处分歧里，14 条判为标注员错、
89 条判为工具错、1 条待裁定（复核当时是 106 处，其后一轮修掉 2 处"原子数取自
错误的指称对象"的错值，对应的两条裁定随之退役）。裁定只可能
抬高分数（它不碰工具蒙对的地方），所以原始终值是**下限**、裁定后的值是
**带裁定意见的上限**，真实值在两者之间。须一并说明的是：裁定人即工具的
作者，**自己给自己的工具判分天然偏向自己**。

**加样本后总分从 70.4% 降到 66.4%，一部分是构成差异，不全是工具退化。**
按层级拆开：批一多抽的是子章节，批二多抽的是完整章节，而完整章节本来就难
（批一 level 1 65.7% vs level 2 75.0%；批二完整章节占 10/12）。但**同一
层级内两批仍差约 2.4 个百分点**，"几乎一致"的旧说法已不成立。数字列在
`eval/real/README.md` 里，**不拆开就会把"样本构成变了"读成"结论变了"。**

按章节层级分层（24 篇）：完整章节（level 1）原始 75.0% / 裁定后 78.5%，
子章节（level 2）原始 76.4% / 裁定后 79.2%。子章节**仍然**更准，
与"子章节会漏掉正文别处写过的内容"的直觉相反；但压假阳性之后两者的差距
已从 6 个百分点缩到 1 个百分点以内，这条规律还站得住，只是不再显眼。

**指标同时暴露了工具的主要短板**：`missing` 的精确率曾只有 **0.46**
（裁定后 0.47），报出的缺失里一多半是错的。二轮结束时 145 处分歧里
103 处是"工具报缺失而标注不是"，其中 31 处标注为 `present`（真漏抽）、
38 处为 `ambiguous`、34 处为 `not_applicable`。即**工具倾向于多报缺失**，
与其"假阳性最劝退、宁可漏报不可误报"的设计原则**方向相反**。

该短板已按四层压过一轮（甲 结构层 / 乙-1 部分证据层 / 乙-2 召回层 /
丙 适用性层），`missing` 精确率 **0.46 → 0.60**、`ambiguous` 召回
**0.13 → 0.38**。全过程逐格记账（`eval/real/status_diff.py`，判据是
"对着标注"而不是"对着上一次运行"）：**47 格变动 = 40 修复 / 1 破化 /
5 中性 / 1 待裁定**。那 1 格破化与 1 格待裁定都在同一篇上，作为**已知开口**
留在报告里，详见 `eval/real/README.md`。**其后又单独做了一轮"取值必须来自
正确的指称对象"：2 格变动 = 2 修复 / 0 破化 / 0 中性 / 0 待裁定**，本文
报告的分数均为这一轮之后的数。5 格中性的含义是"旧错新错"，
`missing` 改判成 `ambiguous` 但标注是 `present`，即从一种错换成另一种错，
**不算修复**。另有一格离开了 `not_applicable`（`1007.5359v2|temperature_bath`
→ `ambiguous`，恰是标注的答案），是可审计的包含性承诺唯一的例外。

**另有 44% 的分歧来自 6 篇域外论文**（强子气体、ReaxFF 参数化、恒温振子、
LJ 氩、一维 FPUT 晶格、有限力程粒子模型；二轮时占 34%，本轮这几篇几乎没动，
占比升高是因为分母从 145 降到 104），剔除后 18 篇的一致率：原始
**82.1%** / 宏平均 F1 0.780，裁定后 **86.4% / 0.842**。这是语料筛选问题，
不是抽取问题，报告时必须分开。

早期还有一轮**无标注的假阳性排查**（24 篇跨膜/电解质/无机材料/ReaxFF
场景），暴露了本项目最大的一类假阳性（`"his"` 命中 "**this**"，
24 篇里 20 篇误报）和两类**取值错误**。两轮的问题已逐条固化为
`eval/real/test_regressions.py` 的 **289 条断言**（分 25 组），
该文件不依赖语料，可独立运行。第 15 组钉的是跨文献比较的判断
（哪些差异算发现、条件不成立时怎么退），第 22、23 组钉的是闸门
（两端热浴 = NEMD；WCA 的母名、反应力场的散文写法、可滴定残基），
夹具同样是合成结构。

## 局限

1. 标注集规模不足（合成集 n=2；真实集 24 篇 / 432 判定）。
   真实集已能给出召回率与逐类 F1，但 24 篇仍不足以做统计推断，
   且标注员是模型。扩充到 30-50 篇后才有稳定性可言
2. `--backend rule` 下，规则覆盖不到的开放文本字段一律标缺失，
   这是设计而非缺陷：宁可说"我没读出来"，不可假装读出来了
3. 适用性判定基于关键词，词表边界是在真实语料上逼近出来的：
   已在 24 篇跨领域方法段上把假阳性压到 0，但**换一批语料是否仍成立未被验证**。
   "短键一律需要词边界"这条约束，正是"`opc` 命中 `dopc`"这类
   取值错误逼出来的
4. **`missing` 假阳性仍是最大短板，但已压过一轮。**
   24 篇上 `missing` 精确率 0.46 → 0.60、`ambiguous` 召回 0.13 → 0.38。
   压的办法是给四态里最关键的 `ambiguous` 补上实现，光"多认词"解决不了：
   原先 `ambiguous` 只能从"匹配成功之后"返回，而"有证据但证据不足"恰恰
   是匹配**不成功**的情形，于是这一态在实践中几乎不存在。补上之后
   `missing` 才可能离开 `missing`。剩下的 0.40 不精确里，多数是
   "标注说 present、工具只认出片段"，那要靠继续做**召回**，而召回带进来的
   取值质量是新的风险点（见上面取值一致率那一段）
5. **规则层与字段层的分工是有意的，但容易被误读。**
   例如 PME 未给 rcoulomb：字段层报 `present`（方法确实报告了），
   由规则 R-10 指出缺的子参数。这不是漏报，但只看字段表会以为没问题。
   `schema/md_method.yaml` 里"属 important 缺失"的措辞指的是**规则层**
   的严重度，不是字段状态，这处措辞已改写
6. **适用性判定存在一条刻意不做的边界。**
   非经典势（ReaxFF / Brenner / Tersoff / 粗粒化 / 机器学习势）下，
   电静力、键约束、色散校正是否适用**取决于势函数类别**。
   没有实现这张映射表，因为物理上不够干净：ReaxFF 带 QEq 电荷、
   因而**有**电静力，Brenner/Tersoff 没有。一刀切"反应势 → 无电静力"
   会产出**自信的错答案**，比现在的"多报几条缺失"更糟。
   这是规则化适用性判定的已知边界
7. **恒压器适用性只认显式 NPT。**
   曾把判据放宽为"只要没写明定容系综就报缺失"，在 12 篇真实语料上
   净亏（改对 3 篇、改错 5 篇）：定容 NEMD、固定晶格固体、表面板
   这些体系里恒压器**物理上就不存在**，而判断这一点需要"这是固定晶格
   固体/定容装置"的领域知识，不是改一行判据能做到的。
   按"宁可漏报不可误报"的既定优先级改回
8. **有限尺寸外推未实现**，NEMD 的 κ 与盒子长度近似线性，
   需多尺寸外推才能与实验对照；当前只做到"发现未报告并报警"。
   与此相关的一处已知开口：`1805.00269v1` 一篇里报了**两个**被模拟的体系
   （体硅 1728、硅烯 8640），抽取器只取第一个——这是"只报了一个指称对象"，
   不是"取错指称对象"。指称对象错（把训练集/化学表示的原子数当成体系规模）
   已修过一轮，账本 2 变动 = 2 修复 / 0 破化，但那张否决表是**语境模式的
   白名单**，没写进去的指称对象仍可能蒙混过关
9. **生成的输入文件不是可直接运行的完整算例。** GROMACS 侧缺 `.top`
   （力场与拓扑），LAMMPS 侧缺力场参数文件与结构文件（`TODO.forcefield`
   与 `TODO.data`）。这是有意的：这两样在文献里几乎从不完整给出，
   伪造它们等于交付一个"能跑但跑的不是原来体系"的结果。
   工具负责的是**把必须人工补的东西明确标出来**，而不是假装补上了。
10. **混合规则依赖力场族识别，未知力场只能留 TODO。**
    `MIXING_BY_FF` 目前覆盖 AMBER / GAFF / CHARMM / OPLS / COMPASS / PCFF / CFF。
    DREIDING 等其他力场落到 `# pair_modify mix TODO` 分支，
    这与第 9 条同源：混合规则我未能逐族坐实，宁可留空。
    对**读脚本**的 `--check-lammps` 而言边界更宽：它无法从脚本反推力场族，
    因此只能检查"这一行在不在"，无法判断在的那一行**值对不对**。
11. **跨文献比较只报"可比不可比"，不修正。** 发现取值分歧后，
    工具指不出哪一篇是对的，那需要独立证据（实验值、复算），
    不是方法段里能读出来的东西。它的产出是**一张需要人工对齐的清单**。
12. **分组依据是场景标志，不是研究主题。** `--flag heat_transport`
    选出的是"在做热输运的那批文献"，而不是"研究同一个材料的那批"。
    因而它回答的是"这批数据点能不能并列"，不是"它们的数值能否平均"。
    真要合并，还需材料体系、温度、相态一致，这些不在 schema 内。
