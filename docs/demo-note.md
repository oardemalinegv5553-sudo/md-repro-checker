# MD 方法段可复现性检查器：Demo 说明

> 代码与数据：`md-repro-checker/`


---

## 1. 问题定义

分子动力学模拟的复现失败，绝大多数不发生在代码层面。代码是公开的、力场是公开的、
软件是开源的，但**把一篇文献的方法段变成一份能跑出同样数字的输入文件**这件事，
目前仍然高度依赖人力，且失败率很高。

失败的具体形态是可以枚举的。以下每一条都来自对文献方法段的实际检查
（演示用的是构造文本，但写入的缺陷都是这一领域的常见写法）：

| 缺陷形态 | 具体例子 | 后果 |
|---|---|---|
| 字段缺失 | 报告了 NEMD 热导率，却不给体系尺寸 | 有限尺寸效应无法评估，κ 无法与实验对照 |
| **取值有误** | 同一段里既写"冷热浴 315/285 K"，又写"ΔT 扫描 20/40 K" | 后者被误读为冷浴温度，得到 κ 依赖 ΔT 的错误结论 |
| 跨字段矛盾 | 声明 NPT 系综，却从头到尾没提恒压器 | 体系状态未定义，根本无法开始复现 |
| 场景性缺失 | 同一字段缺失，算结合自由能是小事，算热导率是致命的 | 通用检查器按统一标准报警，重要信号被噪声淹没 |
| 假阳性 | 干态聚合物熔体被报"未报告水模型" | 使用者连正确的提示一起不再相信 |

前四条是**漏报**，第五条是**误报**。工程实践里第五条更致命：
一个只会报警、不会闭嘴的检查器，最终会被关掉。

因此本 Demo 的核心判断是两条：

1. **"文献没写"与"本文体系不存在这个问题"必须区分。** 二者的数据表现完全相同
   （字段为空），但含义相反。
2. **取值错误比字段缺失更危险。** 缺失会被看见，错值不会，它会被当作事实使用。

---

## 2. 核心思路

把"复现一篇 MD 文献需要知道什么"这件事，从**隐含经验**变成**显式知识资产**，
然后用这份知识去驱动抽取、校验和输入生成。

关键设计是把知识分成两层，各自回答一个不同的问题：

```
schema/md_method.yaml      每个字段"是什么、为什么重要"
                           18 个字段，按 critical / important / contextual 分层

schema/sensitivity.yaml    在"这个具体场景下"，它缺失会让结果偏多少
                           条件化：when {heat_transport: true} 才触发
```

这两层分开是必要的。`thermostat` 在任何 MD 研究里都该报告，
但**只有算热导率时**，Berendsen 恒温器压制涨落、导致 κ 被系统性低估这件事
才是致命的，算结合自由能时同一个恒温器无关紧要。

通用文献解析工具能告诉你 `thermostat: missing`。
只有懂 MD 的人能告诉你"因为你在算热导率，所以这一条让结论直接不可用"。

**这就是本 Demo 相对通用解析工具的增量所在。**

## 3. 系统结构

```
                      ┌──────────────────────────────────┐
   文献方法段  ──────► │  extract.py      规则 + LLM 混合  │
                      └──────────────┬───────────────────┘
                                     │  统一结构化字段
                                     ▼
   知识层  ──────────► ┌──────────────────────────────────┐
   schema/*.yaml       │  validate.py   缺失/歧义/一致性/  │
                       │                敏感性归因/评分     │
                       └──────────────┬───────────────────┘
                                      │
                    ┌─────────────────┼──────────────────┐
                    ▼                 ▼                  ▼
            build_inputs.py     检查单报告        convergence.py
            GROMACS/LAMMPS/     (人读)           模拟结果有效性判定
            OpenMM + 来源标注                     (A/B/C/D 分级)
                    │
                    └─► check_lammps()  也可从 CLI 独立调用，
                        检查别人写好的 .lmp 脚本

   ── 以下换分析单元：从「一篇」到「一组」──────────────
   一组方法段 ──────► corpus.py   横向可比性：取值分歧 /
                                  报告不全 / 集体缺失
```

五段松耦合，每段可单独调用。真实场景里大多数使用者只需要其中一段，
强行串成黑盒反而是负担。生成器与检查器**共用同一套判据**：
能发现自己生成的文件里的问题，也必须能发现别人手写脚本里的同一类问题。

前四段的分析单元是**一篇**，第五段是**一组**，见 3.7。

### 3.1 抽取层：规则与 LLM 的分工

分界线由**字段性质**决定，不由"哪个更先进"决定：

- **规则**（schema 的 18 字段**全部**）：高精度、可枚举。力场版本、水模型、
  恒温器类型、时间步、截断半径、系综、软件版本，这些有稳定写法，
  正则的精确率高于 LLM，且零成本、可审计、输出确定。
  早期版本曾把 `software`、`initial_structure` 也归入 LLM 侧，
  实测完全可以正则化，已收回。
- **LLM**（目前仅 `missing_residues_note` 一个字段，且不在 schema 的 18 字段内）：
  开放文本，需要读句子语义。缺失残基处理、建模步骤描述这类。

抽取结果统一为：

```json
{
  "force_field": {
    "value": "AMBER99SB-ILDN",
    "status": "present",              // present | missing | ambiguous | not_applicable
    "confidence": "high",
    "evidence": {"quote": "AMBER99SB-ILDN force field", "offset": 1247},
    "note": ""
  }
}
```

`status` 四态而非二态，是前面第 1 节那个判断的直接落地。
`evidence` 保留原文片段与偏移量，使每一条结论都可人工复核，
一个不能被复核的自动结论，在科研场景里没有价值。

### 3.2 让"模型的判断"落成"物理的检查"

`extract.py:detect_context()` 判定体系属于哪一类场景（是否含蛋白、是否含配体、
是否显式溶剂、是否算热输运）。这张**适用性表**被两处共用，且只有一份定义：

```python
_APPLICABILITY = {
    "water_model":        lambda c: c.get("explicit_solvent", True),
    "protonation_state":  lambda c: c.get("protein_present", False),
    "correlation_window": lambda c: c.get("heat_transport", False),
    ...
}
```

- **抽取阶段**用它做闸门，阻止正则误命中
  （聚合物熔体用 GAFF2 描述主链，不应被记为"配体参数"）；
- **补全阶段**用它把"没写"与"不存在"区分开。

两处若各自维护一份，迟早漂移，届时同一字段在不同阶段会得到矛盾结论。

### 3.3 输入生成层：来源标注

`build_inputs.py` 的核心是**逐参数标注来源**，模板填空只是外壳：

| 来源 | 含义 |
|---|---|
| `paper` | 文献明确报告，可直接复现 |
| `default` | 文献未报告，工具填入推荐默认值，**复现结果与原研究必有差异** |
| `builtin` | 生成器固定值（如输出频率），不影响物理 |

第三类必须让流水线**显式失败**。理由回到第 1 节：
一个静默填了默认值的输入文件，跑出来的结果看起来完全正常。

来源表汇总成 `provenance.json`，同时写入报告：

```
  统计: paper 5 · default 11 · builtin 15

  以下参数原研究未报告，由工具填入默认值：
      DispCorr, rcoulomb, rvdw, tau-p, tau-t, ...
      → 若要真正复现，这些必须向作者确认，或做敏感性检验。

【无法默认、必须由文献提供的字段】
  !! correlation_window   !! dispersion_correction   !! system_size
  → 这些字段缺失时，生成的输入文件不构成对原研究的复现。
```

最后那一节的字段由敏感性归因层传进来，清单本身是动态的：
`cli.py` 收集本场景下 severity 为 high 的缺失字段，交给生成器。
**判断归知识层，执行归生成器。**

### 3.4 LAMMPS 侧：四条硬规则

LAMMPS 与 GROMACS 的差别不在语法，在于**它不会替你兜底**。
以下四条都是"写错了不报错、只是数不对"的地方，生成器因此不肯默认：

| 规则 | 理由 |
|---|---|
| 拒绝伪造力场参数 | LAMMPS 不读力场库。生成 `include TODO.forcefield` 而不是编一套 `pair_coeff` |
| PME 必须成对出现 | `lj/cut/coul/long` 与 `kspace_style pppm` 缺一不可，只写 `coul/cut` 会静默退化为纯截断库仑 |
| `special_bonds` 挂在力场上 | 1-4 非键缩放是力场定义的一部分，不是各阶段各写各的运行参数 |
| `pair_modify mix` 挂在力场上 | LJ 交叉项混合规则同样由力场族决定，而且**有默认值** |

第四条是本项目"静默失效"论点最纯粹的样本。LAMMPS 默认 `mix geometric`
（σ 取几何平均），而 AMBER / GAFF / CHARMM 用的是 Lorentz-Berthelot
（σ 取算术平均），COMPASS / PCFF 用六次方规则。**OPLS-AA 是这里的例外：
它用的就是几何平均，与默认值一致**（GROMACS 手册 comb-rule 3 原文
"This last rule is used by the OPLS force field"）。所以"漏写 mix"对哪一族
有害取决于力场族，这也正是 `--check-lammps` 只能报警、不能判错的原因。
漏写这一行时：

- LAMMPS **不报错、不警告**，脚本照常跑完
- 所有 I≠J 交叉对的 σ 系统性偏移。偏差大小由 AM-GM 不等式决定：
  算术平均恒 ≥ 几何平均，差值随 σ_i 与 σ_j 的差距单调增大，
  轻原子与重原子配对时最明显，同类原子之间则无差别
- **从能量项上完全看不出来**：源码 `src/pair.cpp` 的 `mix_energy()` 在
  `geometric` 与 `arithmetic` 下返回同一个值 `sqrt(eps1*eps2)`，
  只有 `mix_distance()` 不同，ε 不受影响，只有 σ 变

`DREIDING` 刻意不在映射表里：混合规则未能逐族坐实，与其猜一个值写进去，
不如落到 `# pair_modify mix TODO`。这与第一条硬规则同源，
**不确定时留空比填错更安全**，因为填错的值不会被看见。

### 3.5 检查别人写好的脚本

生成器与检查器共用同一套判据。能发现自己生成的文件里的问题，也必须能发现
别人手写脚本里的同一类问题：

```
$ python -m src.cli --check-lammps 现成的.lmp
```

进**错误**的（脚本一定有问题）：命令名非法、重复 ID、两个恒温 fix 的 group
都是 `all`、有 `run` 步数却没有任何积分器 fix（原子永远不动，跑满步数、
输出齐全、数值稳定）。

进**警告**的（跑得完，但可能不是你想要的那个物理）：有 `lj/cut` 系
`pair_style` 却没有任何 `pair_modify ... mix`。**只有错误产生非零退出码**，
无法从脚本反推力场族，而"所有交叉对都由 `pair_coeff` 显式给定"的脚本
确实不需要这一行，判据不足以断定时工具只提示、不拦路。

### 3.6 结果判定层：不输出裸数值

`convergence.py` 回答的是最后一个问题：按这些参数跑出来之后，这个数能不能信。

它刻意不输出一个裸的 κ 数值，而是输出
**可信度等级 + 判据明细 + 证据**。理由很直接：

> 一个未收敛的 κ 和一个收敛的 κ，在数值上无法区分，
> 但在科研决策中的价值截然不同。

四个判据：

| 判据 | 检查内容 | 针对的失败模式 |
|---|---|---|
| J1 | Green-Kubo κ(t) 的多窗口一致性 | 统计不足，误差棒掩盖真实差异 |
| J2 | 平台区线性漂移 | κ(t) 仍在爬升，取在了未收敛区 |
| J3 | NEMD 温度剖面线性度（R²）+ 单调性 | ΔT 过大，偏离线性响应区 |
| J4 | NVE 段总能量漂移 | 积分不稳定，结果不可用 |

其中 J1/J2 先剔除前 30% 的关联时间再判定。
Green-Kubo 的 κ(t) 前期必然单调上升，把它算进平台区，
正是"看起来平滑所以收敛了"这一误判的主要来源。

### 3.7 跨文献层：换一个分析单元

前六节问的都是"**这一篇**够不够复现"。但真实使用场景里紧接着还有一问：

> 从这些文献里抄下来的 κ，能不能放进同一张表比较？

`corpus.py` 把分析单元从「一篇」换成「一组」，回答这个问题。

它**没有引入任何新的领域知识**，`sensitivity.yaml` 里
"未报告恒温器 = 该 κ 值不可与其他文献横向比较"早就写好了，
只是一直被施加在单篇上。这一段的全部内容是换个单元把同一套知识
重新施加一遍。因此它不新增一条领域判断，却能看到逐篇看不到的三类现象：

| 类型 | 含义 | 逐篇工具为什么看不到 |
|---|---|---|
| **取值分歧** | 同一物理量，不同文献给出不可通约的取值 | 单篇只能各说各的 |
| **报告不全** | 取值一致，但有几篇没报 | 缺失被逐篇平摊掉了 |
| **集体缺失** | 该组**无一篇**报告某关键量 | 每篇都只是"缺一个字段" |

在 11 篇热输运文献（arXiv，公开）上的实测：

```
--------------------------------------------------------------------------
!  [集体缺失] 统计窗口与关联时间 (correlation_window)
    报告 0/11 篇，缺失 11 篇
--------------------------------------------------------------------------
!  [取值分歧] 热流计算方法 (heat_flux_method)
    报告 9/11 篇，缺失 2 篇
      · Direct NEMD  (2 篇)
      · EMD  (1 篇)
      · Green-Kubo  (4 篇)
      · RNEMD (Muller-Plathe)  (2 篇)
--------------------------------------------------------------------------
!  [报告不全] 体系规模 (system_size)
    报告 1/11 篇，缺失 10 篇
      · {"atoms": 1728}  (1 篇)
--------------------------------------------------------------------------
-  [取值分歧] 冷热浴温度与梯度 (temperature_bath)
    报告 2/11 篇，缺失 9 篇
      · {"delta_K": 20}  (1 篇)
      · {"delta_K": 60}  (1 篇)
      [此处省略 2 个块：初始结构来源 (initial_structure)、恒温器类型与耦合常数 (thermostat)]
==========================================================================
结论: 不可横向比较
      冲突 6 项（取值分歧 3 · 集体缺失 1 · 报告不全 2），其中阻断可比性 5 项
```

`correlation_window` 是这里最重的一条：**全组 0 篇报告**，单独看每篇都
只是"缺了一个字段"，合起来看才是"这一批文献的 κ 值没有任何一篇给出了
收敛证据"。`temperature_bath` 则是另一面：有两篇报了，但一个 ΔT=20 K、
一个 ΔT=60 K，**报了反而暴露它们不在同一个线性响应区**，
照样不能并列。`system_size` 只有 1 篇报告，这一组**没有一个尺寸可做
外推，也没有两个可比的尺寸**。

#### 这一段曾经报出一个假分歧

`system_size` 这一行最早长这样：

```
!  [取值分歧] 体系规模 (system_size)
    报告 2/11 篇，缺失 9 篇
      · {"atoms": 1728}  (1 篇)
      · {"atoms": 54840}  (1 篇)
```

1728 是真的（体硅的模拟胞），54840 是**假的**：它出自
`2207.13405` 的 "914 structures with 54840 atoms in total"，
而那句话说的是 NEP 势的**训练集**规模——被模拟的硅烯全文没给原子数。
抽取器只认 `<数字> atoms` 这个裸模式，不认识数字属于谁，
于是把一个训练集尺寸填进了"体系规模"。

这正是本工具反复回到的那条线：**缺失会被看见，错值不会**。
一篇方法段缺了体系规模，读者一眼能看出来；但检查单上写着
"54840 atoms"，看起来就是"这篇报了，而且报得很具体"。
更糟的是它在这里**自己造出了一条分歧**——工具本来是来判断
"这几篇能不能比"的，结果它把一个抽取错误当成了文献之间的协议冲突。

修法不是给这篇打补丁（那是过拟合），而是让原子数必须**归属于被模拟的
体系**：训练集/数据集、化学表示（`SMILES` 表示里"每条链约 200 atoms"）、
单条链的规模，这几类语境里的原子数一律不取。`2207.13405` 因此改报它
真正给了的盒子尺寸（W=13.3 nm），落在 spec 规定的 `ambiguous`；
`1805.00269v1` 的真值 1728 不受影响。同一类错还有第二个实例
（`2602.17595v1` 的 200 atoms 是化学表示里**单条链**的规模），一并修掉。
全语料 432 格里只有这 2 格动，账本 **2 变动 = 2 修复 / 0 破化 / 0 中性
/ 0 待裁定**；两条对应的旧裁定随之退役。都钉进了回归测试第 25 组。

**这一修顺带从反面证实了本项目的核心命题。** `2207.13405` 改报
`ambiguous` 之后，检查单上**多出**一行
`R-05 热输运计算未报告体系尺寸`——那个假的具体值此前一直在让这条警告
闭嘴：**填一个假值，反而不报缺失了**。"缺失会被看见，错值不会"在这里
不是一句口号，是一次可复现的对照。（严格说 R-05 的话术比判据宽：
这篇确实报了盒子尺寸，只是没报原子数。`ambiguous` 与 `missing` 在
`_present()` 眼里同属"未确立取值"，所以警告照发。这条边界记在这里，
不顺手改它。）

两处刻意留下的开口：`1805.00269v1` 一篇里报了**两个**被模拟的体系
（体硅 1728、硅烯 8640），都是真模拟胞，抽取器只取第一个——这是
"只报了一个指称对象"，不是"取错指称对象"，性质较轻；以及上面那张
否决表是**语境模式的白名单**，没写进去的指称对象仍可能蒙混过关。

两条刻意的保守设计：

- **没有依据的差异不构成发现。** 只比较 `sensitivity.yaml` 写了影响规则的
  字段。该组在 `timestep` 上有 4 种取值，但知识层没为它写规则，不报。
  有差异就报，等于再造一个劝退的假阳性工具。
- **字典取值按公共键交集比较。** `{type: Nose-Hoover, coupling: 0.1}` 与
  `{type: Nose-Hoover}` 的公共键是 `{type}`，两边同为 Nose-Hoover，
  这是**报告不全**，不是协议分歧。不取交集的话，每多一篇少写一个可选键
  就凭空多一条假分歧。

分组依据是 `extract.py` 已经在算的场景标志，不是新加的判断：
`--flag` 换成 `protein_present` / `ligand_present` / `explicit_solvent`
即可复用到别的场景。**不指定时自动挑最大的组。**

## 4. 输出结构定义与强约束建模

对 LLM 参与的部分，用 JSON schema + 显式置信度做约束，而非自由生成：

- 每个字段的 `why` 说明（为什么这个字段重要、缺失会导致什么后果）**一并喂给模型**。
  这既是提示词，也是约束，模型在判断"要不要把这个标为 ambiguous"时，
  依据的是领域规则而非语言直觉。
- `why` 与 `state_rule` 分两个键写。`why` 是纯理由，且**会被原样印在检查单里**
  包括印在【字段缺失】块下面；`state_rule`（"什么情况判哪一态"）是机器用的，
  只喂给模型、不进报告。分开之前，`system_size` 的 `why` 以"属 ambiguity"结尾，
  于是那句话会被印在【未报告 体系规模】下面：判定是对的，读起来却像工具在自我否定。
- 要求模型输出 `confidence` 与 `note`，把不确定的部分**显式暴露**出来，
  而不是让它消失在流畅的措辞里。
- 规则层若以 high 置信命中，则保留规则结果，不被 LLM 覆盖
  （`extract.py` 中"规则精确率更高"的判断）。
- **请求的后端没跑成，报告必须自己说。** 检查单会核对"请求的后端"与"实际生效的
  后端"，不一致时显式警告并附上原因，否则一次静默降级会以满分的姿态交出去。

### 5.2 输入文件生成

```
$ python -m src.cli examples/case-01/methods_v1_typical.txt --build

  生成  em.mdp  nvt.mdp  npt.mdp  prod.mdp
  生成  em.lmp  nvt.lmp  npt.lmp  prod.lmp
  生成  openmm_skeleton.py  provenance.json
  统计 (GROMACS): paper 5 · default 11 · builtin 15
  统计 (LAMMPS):  paper 7 · default  8 · builtin 14
```

**两套引擎的来源表分开统计。** 同一个物理量在 `.mdp` 与 `.lmp` 里的表达方式
与覆盖面都不同（如 1-4 非键缩放，GROMACS 侧是 `fudgeLJ/fudgeQQ`，
LAMMPS 侧是挂在力场上的 `special_bonds`），混在一张表里会让"这个默认值
属于哪个引擎"变得不可判断，而默认值恰恰是最需要被逐一确认的东西。

生成的 `prod.mdp`（节选）：

```
integrator              = md
dt                      = 0.002          ; 文献报告 2 fs，GROMACS 单位为 ps
nsteps                  = 10000000       ; 20 ns
coulombtype             = PME
rcoulomb                = 1.0            ; ← default：文献未报告
DispCorr                = EnerPres       ; ← default
tcoupl                  = berendsen      ; ← paper：文献确实用了 Berendsen
pcoupl                  = Parrinello-Rahman   ; ← paper
```

单位换算是这一层必须处理好的细节：文献惯例用 fs 报告时间步，
GROMACS 的 `dt` 单位是 ps。直接把 `2` 写进 `dt` 会得到 2 ps 的步长，
模拟瞬间炸开，而报错信息不会指向这里。

生成的 `prod.lmp`（节选，同一份方法段）：

```
special_bonds   amber
# AMBER/GAFF 约定：1-4 库仑缩放 5/6，1-4 LJ 缩放 1/2；此值由力场决定，所有阶段必须一致
include         TODO.forcefield
#   LAMMPS 不读取力场库；用 fftool / msi2lmp / Moltemplate / 自备参数文件生成

pair_style      lj/cut/coul/long 10.0
kspace_style    pppm 1.0e-4
pair_modify     tail yes
pair_modify     mix arithmetic
# AMBER/GAFF 用 Lorentz-Berthelot：ε 几何平均、σ 算术平均
# LAMMPS 默认是 geometric；漏写不报错，只让所有 I≠J 交叉对的 σ 偏移
```

`special_bonds amber` 与 `pair_modify mix arithmetic` 的来源都标为 `paper`，
但它们并非从方法段里读到的字符串，而是由文献报告的**力场名**（GAFF2）推得的。
这正是本工具想表达的：力场一旦确定，一批非键设置就随之确定，作者不必逐一写出。
**漏掉它们的代价不是报错，是数不对。**

### 5.3 结果有效性判定

`python -m src.convergence --demo`（数据为合成，固定随机种子）：

    κ = 0.0878 ± 0.0010                  κ = 0.1581 ± 0.0257

### 5.5 度量：合成集上的冒烟测试

没有标注集，就无法区分"这个工具确实发现了问题"与"这个工具什么都发现不了"。
`eval/score.py` 在 18 字段 × 2 版本的**合成**标注上计算四类指标：

```
$ python eval/score.py

案例 v1
状态准确率      100.0%    三态宏平均 F1  1.000
    present          P 1.00  R 1.00  F1 1.00   (n=12)
    missing          P 1.00  R 1.00  F1 1.00   (n=3)
    not_applicable   P 1.00  R 1.00  F1 1.00   (n=3)
取值准确率      100.0%    (仅统计标注给出值的字段)
一致性规则      P 1.00  R 1.00  F1 1.00
    命中: R-02, R-03, R-05, R-08, R-10, R-11, R-12
可执行率        9/9 个生成文件通过语法检查 (.mdp/.lmp/OpenMM), unresolved 0 → 通过
评分            28 / 100  [D]
...
平均三态宏 F1   1.000    平均取值准确率  100.0%    假阳性总数 0
```

**这个 100% 不是准确率的证据。** n=2 只能暴露错误类型；更关键的是，
本集的标注与抽取出自同一作者，两边一致更多说明规则符合自己的预期，
不说明它对真实文献管用。命令自身在末尾就把这句话打了出来
（见 `examples/case-01/expected/06_eval.txt`），不等人去追问。

可执行率这一项横跨三套引擎（4 个 `.mdp` + 4 个 `.lmp` + 1 个 OpenMM 骨架），
判定标准各不相同，所以分开列引擎而不是笼统写成一个数。

三类指标刻意分开，对应三类不同的失败：

1. **状态**用三态而非二分类计算。把 `missing` 与 `not_applicable`
   合并成"字段为空"，恰好会掩盖假阳性这个最严重的问题。
2. **取值**单独统计。状态判对但值抓错比状态判错更危险。
   开发过程中实际出现过两个：`cold_K=30`（抓到了 ΔT 扫描点）、
   `replicas=30`（抓到了"30 repeat units"的体系构成），
   两个都是"看起来合理"的错值。
3. **假阳性总数**单列，并在 `labels` 中维护 `rules_forbidden` 列表专门用来抓它。
   `R-06`（对干态聚合物熔体误报水模型缺失）就是这样被发现的。

指标零样本类别会被排除而非计零，若某版本标注不含 `missing` 样本，
该类的 0/0 被算成 F1=0 会把完美抽取压成 0.667，**指标本身在撒谎**。

#### 在真实文献上：24 篇独立标注

合成集上全对说明不了什么，所以在 arXiv 真实方法段上另做了一轮，
**独立标注 24 篇（432 个判定）**（语料因版权不随提交分发）：

| 指标 | 24 篇，原始 | 24 篇，裁定后 | 压假阳性后（原始） | 压假阳性后（裁定） | 批一裁定后 | 批二裁定后 |
|---|---|---|---|---|---|---|
| 状态一致率 | 66.4% | 69.7% | **75.9%** | **79.2%** | **75.9%** | 63.4% |
| 四态宏平均 F1 | 0.580 | 0.651 | **0.716** | **0.770** | **0.718** | 0.570 |
| 取值一致率 | 85.9% (n=64) | 85.9% | **74.7% (n=87)** | 74.7% | 85.7% | 86.1% |

「压假阳性」两列是最近一轮的结果（已含其后的"取值必须来自正确的指称对象"
一轮，读者跑 `python eval/real/score_real.py [--adjudicated]` 能复现；
`批一裁定后` 与它同为 75.9% 是巧合，宏平均 F1 不同：0.718 vs 0.716），
**必须连同它的代价一起读**：状态一致率涨了
9 个百分点，取值一致率掉了 11 个，新召回的 23 个可比格子里只有 10 格取值
是对的。多报一个 `present` 而取值错，比报 `missing` 更糟，所以下一轮的主攻
方向是取值质量而不是状态一致率。

**标注的独立性**：标注员只看方法段原文与 schema 生成的字段说明，看不到 `src/`、
也看不到彼此的标注，否则标注会被被测的实现污染，那是自证。
**但标注员是模型而非人工**：两批各 12 份文件分别写在 88 秒与 155 秒内，
不可能手工完成。这一点如实写明，协议能隔断的都隔断了，但
"同一个模型既写工具又当标注员"这一层隔不断，**同源偏置无法排除**。

**两个数都报，不挑大的那个。** 原始一致率把每处分歧都算作工具的错，而定标人会错：
压假阳性之后的 104 处分歧逐条复核，判出 **14 条标注员错、89 条工具错、1 条未裁定**
（复核当时是 106 处；其后一轮修掉 2 处原子数归属错误，两条裁定随之退役。
未裁定的那 1 条正是本轮唯一一处 `broken`，见下）。裁定只可能抬高分数
（不碰工具蒙对的地方），所以原始终值是下限、裁定后的值是上限，真值在两者之间。
须一并说明的是：裁定人即工具的作者，**自己给自己的工具判分天然偏向自己**。

**加样本后总分从 70.4% 降到 66.4%，一部分是构成差异，不全是工具退化。**
按层级拆开：批一多抽的是子章节，批二多抽的是完整章节，而完整章节本来就难。
但**同一层级内两批仍差约 2.4 个百分点**，"几乎一致"的旧说法已不成立。
**不拆开就会把"样本构成变了"读成"结论变了"。**

**主要短板**：`missing` 精确率曾只有 **0.46**（裁定后 0.47），报出的缺失里
一多半是错的，与其"假阳性最劝退、宁可漏报不可误报"的设计原则**方向相反**。
针对这一点做了一轮，分四层改（打通力场的适用性表与报告表、给 `ambiguous`
补上"有证据但不足"这条路径、扩抽取器召回、修正三条适用性闸门），
每层先拍快照再改、逐格对账（`eval/real/status_diff.py`）：

| | 二轮 | 本轮 | 本轮（裁定后） |
|---|---|---|---|
| 状态一致率 | 66.4% | **75.9%** | **79.2%** |
| `missing` 精确率 | 0.46 | **0.60** | 0.61 |
| `ambiguous` 召回率 | 0.13 | **0.38** | 0.54 |

账本全程 **40 fixed / 1 broken / 5 neutral / 1 disputed**，`broken` 只有 1 处。
**但代价是取值一致率从 85.9% 掉到 74.7%**：新召回的 23 个可比格子里只有 10 格
取值是对的。**"缺失会被看见，错值不会"**，所以 0.60 是下限不是终点，
下一轮的主攻方向是取值质量。

**另有 44% 的分歧来自 6 篇域外论文**（强子气体 EoS、ReaxFF 参数化、恒温振子、
LJ 氩热扩散、一维 FPUT 晶格、有限力程粒子模型；二轮时占 34%，本轮这些篇几乎
没动，占比升高是因为分母变小）。剔除后 18 篇的一致率：原始 82.1% / 宏平均 F1
0.780，裁定后 **86.4% / 0.842**。这是语料筛选问题不是抽取问题，
**报告时要么剔除、要么分层，不能混在一起当成工具的错**。

两轮真实语料排查暴露的缺陷（时间步间隔写死、采样间隔被当成模拟时长、
PME/PPPM 别名、版本号前置、`t?leap` 命中 "temperature leaps"、散文式耦合常数、
小写 `npt` 使恒压器整个字段消失、势函数能力表与报告表互不知道对方、
`ambiguous` 这一态根本没实现等）已逐条固化为
`eval/real/test_regressions.py` 的 **289 条断言**（分 25 组），该文件不依赖语料、可独立运行。
第 15 组钉的是跨文献比较的判断（哪些差异算发现、条件不成立时怎么退）；
第 18 组钉部分证据层，其中**"抽取器命中赢过部分证据"与"适用性闸门赢过部分
证据"这两条顺序判据**（第 22 组里另有一处端到端的）是这一层能被信任的前提，
顺序不是风格问题：闸门若排在部分证据之后，24 篇里 17 篇的恒压器会从
`not_applicable` 整体变成 `ambiguous`。夹具同样是合成结构。

## 6. 局限与后续

诚实说明边界，比宣称能力更重要。

**当前局限**

1. **标注规模仍不足**：合成集 2 个版本；真实集 24 篇 / 432 判定。
   真实集已能给出召回率与逐类 F1，但 24 篇不足以做统计推断，且标注员是模型。
   扩充到 30-50 段后才谈得上稳定。
2. **`missing` 假阳性仍是最大短板，只是压小了一截**：真实语料上 `missing`
   精确率 0.60（原 0.46），报出的缺失里仍有四成是错的；`ambiguous` 召回
   0.38（原 0.13），六成多的"提到了但不够具体"仍被当成"没写"或"写了"。
   **本轮的真实代价在取值侧**：取值一致率从 85.9% 降到 74.7%，新召回的
   23 个可比格子里只有 10 格取值是对的（`initial_structure` 的 4 格全错）。
   状态一致率涨、取值一致率跌，**换来的不全是进步**，下一轮优先修取值。
3. **适用性判定基于关键词**，对跨领域体系（离子液体、金属有机框架、
   生物膜）会失效。势函数类别 → 字段是否适用的映射表（`FF_FAMILIES`）
   已实现，把 NA→missing 从 55 例压到 31 例；**刻意不做的**是靠"这是粗粒化
   体系 / 这是反应体系"这类间接信号去推定整族字段不适用，四条候选
   （Martini 粗粒化、文献转引的势、`small molecules` 当配体、热流词汇计数
   当闸门）全部量化后否决，逐条实测见 `eval/real/README.md`。
   理由一致：**判不出来时应当承认判不出来，而不是猜**。工具现已有一条
   "有证据但不足 → `ambiguous`"的路径来承载这一点。
4. **有限尺寸外推未实现**。NEMD 的 κ 与盒子长度近似线性，
   必须多尺寸外推才能与实验对照。当前只做到"发现体系尺寸未报告并报警"，
   没有做外推本身。
5. **生成的输入文件不是可直接运行的完整算例**：GROMACS 侧缺 `.top`，
   LAMMPS 侧缺力场参数文件与结构文件（`TODO.forcefield` / `TODO.data`）。
   这是有意的，这两样在文献里几乎从不完整给出，伪造它们等于交付一个
   "能跑但跑的不是原来体系"的结果。工具负责把必须人工补的东西
   **明确标出来**，而不是假装补上了。NAMD 模板仍未覆盖。
6. **混合规则依赖力场族识别，未知力场只能留 TODO**：`MIXING_BY_FF` 覆盖
   AMBER / GAFF / CHARMM / OPLS / COMPASS / PCFF / CFF，DREIDING 等其他力场
   落到 TODO 分支（与第 5 条同源：未能逐族坐实就宁可留空）。对
   `--check-lammps` 而言边界更宽，它无法从脚本反推力场族，只能检查
   "这一行在不在"，**判断不了在的那一行值对不对**。
7. **跨文献比较只报"可比不可比"，不修正，也不判定谁对**。发现取值分歧后，
   工具指不出哪一篇是对的，那需要独立证据（实验值、复算），
   不是方法段里能读出来的东西。产出是**一张需要人工对齐的清单**。
8. **分组依据是场景标志，不是研究主题**。`--flag heat_transport` 选出的是
   "在做热输运的那批文献"，不是"研究同一种材料的那批"。因此它回答的是
   "这批数据点能不能并列"，**不是"它们的数值能否平均"**，真要合并，
   还需材料体系、温度、相态一致，这些不在 schema 内。

**后续方向**

- 用真实公开文献（如 `arXiv` 上带完整方法段的预印本）批量扩充标注集
- 把有限尺寸外推做进 `convergence.py`：读多尺寸结果，拟合 κ(L) 外推至 L→∞
- 给 `corpus.py` 补上"哪一篇是对的"这一步：接入实验值或独立复算结果，
  把"需要人工对齐的清单"推进到"可自动判定的分歧"
- 与文献解析上游打通：方法段通常混在全文里，
  需要先做段落级切分与正文/补充材料对齐
- 把 schema 本身开放成可扩展的：不同子领域（热输运、力学、离子传导）
  各自的字段集与一致性规则

## 7. 与深势方向的关系

本 Demo 想回应的，是 `arXiv 2512.20469`（《Bohrium + SciMaster》，
2025-12-23）在 **§1.2 Four bottlenecks to scaling agentic science** 中列出的四个瓶颈：

| 原文（§1.2） | 本 Demo 的对应做法 |
|---|---|
| workflows are hard to observe and reproduce | 方法段 → 结构化字段 → 输入文件，每一步都有来源标注与原文证据 |
| many tools and laboratory systems are not agent-ready | 统一 JSON schema 输出，含 `status`/`confidence`/`evidence`，机器可直接消费 |
| execution is hard to trace and govern | `provenance.json` 逐参数记录来源；`unresolved` 字段使流水线显式失败而非静默降级 |
| prototype AI Scientist systems are often bespoke, limiting reuse | 五段松耦合、每段可单独调用；知识层是纯 YAML，与代码解耦 |

论文 **§4**（SciMaster 编排层）列出的几个机制，本 Demo 在同一尺度上各自实现了一份：

| 论文 §4 中的机制（原文措辞） | 本 Demo 中的对应物 |
|---|---|
| **Observability, validation gates, and auditability**，工具调用、中间产物、模型调用 "logged with trace metadata" | `provenance.json` 逐参数来源，加每条 finding 的 `evidence.quote/offset` |
| **领域级检查**，"scientific consistency, numerical stability, or experimental feasibility" | `validate.py` 的 12 条一致性规则，含 R-11 的线性响应判据 |
| **State and memory**，中间结果作为 versioned artifacts，"compared across branches, and rolled back when needed" | `convergence.py` 的 A/B/C/D 分级，使"这个数能不能用"可比较、可回退 |

如果 Bohrium 要做 AI4S 资产的"HuggingFace"，
那么数据集里每一条 MD 记录都应当携带**它自己的可复现性元数据**：
用了哪个力场版本、哪些参数来自文献、哪些是默认假设、结果的统计是否收敛。

**但只有逐条元数据还不够。** 一个数据集的价值在于它的记录可以被放在一起
用，而 3.7 的结果说明：11 篇各自"看起来完整"的热输运文献，
合起来看没有任何一篇给出了 κ 的收敛证据，另有三项取值互不可通约。
如果资产库只做逐条收录而不做横向可比性检验，
它收录的是一堆无法并列的数字。
`corpus.py` 是这条流水线里最靠近"数据集质量"的一段。

本 Demo 把这件事的 schema 和判定逻辑先做出来，
单篇尺度上是 `validate.py`，成组尺度上是 `corpus.py`。

**可迁移的部分**：`schema/*.yaml` 的知识组织方式不限于 MD。
任何需要"从非结构化描述生成可执行配置、并标注不确定性"的场景，
都可以复用同一套结构，这对科学智能体的工具层是通用的。
